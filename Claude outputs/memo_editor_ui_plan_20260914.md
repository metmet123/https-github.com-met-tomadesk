# TomaDesk 메모 편집 UI 변경 계획

- 작성일: 2026-09-14
- 근거: 2026-09-14 Phase 1~3 진단 · 사용성 분석(U1~U11) · 공개 앱 벤치마킹 · 개선 시안(아트보드 3장)
- 목표: 본문 붙박이 UI **8줄 → 2줄**, 본문 세로 **554px → 800px 안팎**. **없어지는 기능은 0개.**
- 사용자 확정 제약: **접은 상태에서도 빠른 알림 등록 단축키가 작동해야 한다.** → 4번 항목에 계약으로 못 박았다.

---

## 1. 설계 원칙 세 가지

이 세 줄이 아래 모든 결정의 근거다.

1. **자리를 옮기는 것이지, 없애는 것이 아니다.** 위젯 객체와 그 이름(`self.datetime_input`, `self.quick_buttons`, `self.reminder_save_button` …)은 **그대로 살려 두고 부모만 바꾼다.**
   → 기존 테스트가 이 이름들을 **88회** 참조한다(아래 표). 이름을 유지하면 대부분 그대로 통과한다.
2. **보이는 것과 살아 있는 것을 분리한다.** 팝오버는 껍데기일 뿐이다. 값·시그널·단축키는 팝오버가 닫혀 있어도 항상 동작한다.
3. **팝오버는 최상위 창이 아니라 편집기의 자식 위젯이다.** 포커스가 편집기 밖으로 나가면 `WidgetWithChildrenShortcut` 단축키가 전부 끊긴다.

| 옮길 위젯 | 참조하는 테스트 파일 | 참조 횟수 |
| --- | --- | --- |
| `datetime_input` | 2 | 20 |
| `quick_buttons` | 3 | 17 |
| `format_toolbar` | 6 | 16 |
| `reminder_toggle` | 2 | 10 |
| `reminder_details` | 1 | 4 |
| `actions_host` · `manual_save_button` · `delete_button` | 2 | 12 |
| `saved_status` · `hotkey_toggle` · `below_host` · `color_buttons` · `opacity_combo` | 1~2 | 9 |

## 2. 단계 (Stage 0 → 5)

각 단계는 **따로 배포해도 앱이 돌아가는** 크기로 잘랐다.

### Stage 0 — 결함 먼저 (반나절)

UI를 바꾸기 전에 반드시 끝내야 한다. 특히 결함 D는 시안과 **정면으로 충돌**한다.

| 결함 | 왜 먼저인가 |
| --- | --- |
| **D — Esc가 블록 선택을 못 푼다** (`panel.py:146` 의 `QShortcut(Esc) → go_back`) | 시안의 팝오버는 **Esc로 닫는다**. 지금 상태로 만들면 Esc를 눌렀을 때 팝오버가 닫히는 게 아니라 **이전 메모로 튄다.** 이 충돌을 먼저 정리하지 않으면 Stage 1을 시작할 수 없다. |
| **A·B — 빈 줄에 제목1~4가 안 먹고, 재열기 후 제목이 사라진다** | Stage 2에서 부동 막대에 제목1~4를 넣는다. 깨진 기능을 새 UI에 얹으면 원인이 UI인지 기존 버그인지 구분이 안 된다. |
| **C — 토글 묶기 Ctrl+Z 불능** | 같은 이유. 새 UI에서 재현되면 회귀로 오인된다. |

Esc 정리 방향: **Esc = 취소**(팝오버·부동 막대·블록 선택 닫기), **뒤로 가기는 다른 키로.**
`Alt+Left`는 이미 "접힌 구조에서 부모로 복귀"에 쓰이므로 겹치지 않는 키를 새로 정하고, 단축키 설정창에 노출한다.

### Stage 1 — 속성 칩 줄 (핵심, ~170px 회수)

**새 파일** `alert_notes/note_property_bar.py`
- `PropertyChipBar(QWidget)` — 칩 한 줄. 칩마다 `id`, 아이콘, **값 요약 라벨**, 눌렀을 때 열 패널.
- `PropertyPopover(QFrame)` — **MemoEditor의 자식 위젯**. `raise_()` 로 띄우고 `hide()` 로 닫는다. `QDialog`/`Qt.Popup` 금지(원칙 3).

**`alert_notes/editor.py` 변경**
- `reminder_card`, `hotkey_card`, `below_host`(서식1~3·항상 위·포스트잇), `actions_host`(입력 잠금·색·투명)를 **팝오버의 페이지로 재부모화.** 생성 코드는 손대지 않는다.
- 아래 한 줄에 남는 것: `서식 ▾` · `saved_status` · `manual_save_button` · `delete_button`.
- `reminder_toggle`/`reminder_details`는 **지우지 않는다.** 팝오버 안에서 그대로 쓰거나, 팝오버가 열릴 때 항상 펼친 상태로 둔다(테스트 14회 참조 보호).

**칩 라벨 규칙** (Notion 속성 패턴)

| 칩 | 값 없음 | 값 있음 |
| --- | --- | --- |
| 알림 | `알림` (회색) | `오늘 18:30` (파랑 강조) |
| D-Day | `D-Day` | `D-28 제출 마감` |
| 색 | 색 점만 | 색 점 + `투명 30%` |
| 단축키 | `단축키` | `Ctrl+Alt+M` |
| 그 밖 | `⋯` | 켜진 항목 수 배지 |

**완료 기준**
- 붙박이 위 2줄(제목·칩) + 아래 1줄, 본문 높이 750px 이상(1920×1010 기준)
- 알림·D-Day·매달 반복·색·투명도·입력 잠금·항상 위·포스트잇 모드·전역 단축키·서식1~3이 전부 칩으로 도달 가능
- 기존 회귀 753개 중 실패 0

### Stage 2 — 부동 서식 막대 (~74px 회수)

- **새 클래스** `TextFormatFloatingBar` — `alert_notes/block_action_bar.py`의 `BlockActionBar`를 본뜬다(같은 부모, 같은 `sync()` 패턴, 같은 스타일).
- 트리거: `content_edit.selectionChanged` + 마우스 버튼을 **뗀 뒤**. 드래그 중에는 뜨지 않는다.
- 담을 것: `B I U S` · `제목1~4` · `본문` · `색`.
- **위치 규칙(결함 E의 교훈)**: 선택 범위 **위**에 두되, 위쪽에 가릴 내용이 있으면 **아래**로 내린다. `BlockActionBar.sync()`의 "4px만 있으면 무조건 위" 규칙은 쓰지 않는다.
- 상단 서식 2줄 제거.

**완료 기준**: 글자를 고르면 막대가 뜨고 Esc로 닫힌다. 막대가 본문 첫 줄을 가리지 않는다.

### Stage 3 — 접힌 "서식 ▾" 한 줄 (~40px 회수)

- `TextFormatToolbar`를 아래 한 줄의 `서식 ▾` 버튼에 붙는 **오버레이**로 바꾼다. 본문 위를 덮되 **밀어내지 않는다.**
- 담을 것: 글씨체 · 크기 · 줄 간격 · 서식1~3 · 기본값 · 단축키 · 이미지 · 접기.
- 상태 기억 안 함 — 항상 접힌 채 시작한다(OneNote 리본 방식).
- `format_toolbar` 이름과 공개 메서드(`reload_shortcuts`, `move_presets_to`, `set_auxiliary_button`)는 유지(테스트 16회 참조).

### Stage 4 — 레이아웃·반응형

`alert_notes/panel.py`
- `setStretchFactor(1, 1)` — 편집 칸도 남는 너비를 나눠 갖는다 (지금은 `0:0:1`이라 오늘 요약만 늘어난다).
- 오늘 요약에 `setMaximumWidth(360)`.
- 기본 비율 `700:640:560` → `520:780:400`.
- 오늘 요약이 **셋 다 비면 자동 접기**(펼치기 손잡이만 남김).

`alert_notes/editor.py`
- `content_edit.setMinimumHeight(180 → 320)`.
- `TWO_COLUMN_WIDTH` 900 → 780 (오른쪽 칸이 실제로 필요한 폭은 색상 줄 기준 615px).
- 좁은 창(1080 미만): 목록은 **손잡이만 남는 서랍**, 오늘 요약 숨김, 칩은 앞 3개 + `⋯`.

### Stage 5 — 발견 가능성

- **설명서에 한 장 추가**: 속성 칩 / 부동 서식 막대 / 서식 접기 / 집중 모드 / Alt+클릭 블록 선택.
  (현재 `user_manual_content.py`에서 `줄 간격`·`붙여넣기`·`블록`·`독립 복제`·`모두 접기` 검색 결과 **0건**이다.)
- **설정 추가**: "새 메모는 항상 집중 모드로 열기" (UpNote 패턴).
- **제목 단축키 등록**: `Ctrl+Shift+1~4` → 제목1~4. 지금은 본문만 `Ctrl+Shift+0`이 있고 제목은 없다.
- **단축키 설정창을 목록 겸용으로**: 못 바꾸는 고정 키(Alt+↑↓, Alt+←→, Alt+C, Ctrl+Shift+E, Ctrl+Shift+V, Ctrl+Shift+4/5/7/8/9)도 회색으로 함께 보여 준다.
- **툴팁 오표기 수정**: 글머리표 버튼 툴팁이 `Ctrl+Shift+L`이라고 안내하는데 메모 편집창의 실제 키는 `Ctrl+Shift+5`다(`Ctrl+Shift+L`은 포스트잇 창 전용).
- **Tab/Shift+Tab을 블록 선택에 연결**: 지금은 커서가 있는 한 줄만, 그것도 줄 맨 앞일 때만 들여쓴다.

## 3. 되돌릴 수 있게 만들기

새 설정 키 하나로 **옛 배치와 새 배치를 둘 다 유지**한다.

```
memo_editor_layout = "classic" | "compact"   (기본 compact, 한 달간 classic 유지)
```

- Stage 1~3의 재배치는 전부 이 플래그 하나로 갈린다.
- 위젯 생성 코드는 공통, **부모만 분기**한다. 그래서 분기 비용이 작다.
- 문제가 나오면 설정 한 줄로 되돌리고, 안정되면 `classic` 경로를 지운다.

**DB 스키마 변경 없음.** Phase 1~3과 같은 원칙을 지킨다.

## 4. 빠른 알림 등록 단축키 계약 ★

> 요구: **속성이 접혀 있어도 Alt+Q / Alt+` / Alt+1~6 / Alt+W 가 그대로 동작해야 한다.**

### 지금 상태 (확인함)

```python
# editor.py:950
self.time_shortcuts = bind_time_shortcuts(self, self.store, self._quick_reminder)

# editor.py:885
def _quick_reminder(self, minutes, _label=""):
    self.datetime_input.set_datetime(datetime.now() + timedelta(minutes=minutes))
    self._quick_time_active = False
    self._save_reminder()
```

- 단축키는 **MemoEditor 자신**에 `WidgetWithChildrenShortcut`으로 걸려 있다.
- `_quick_reminder`는 위젯이 **보이는지와 무관하게** 값을 넣고 바로 저장한다.
- 그래서 **지금도 알림 카드를 접어 둔 채 Alt+1이 동작한다.** 이 동작을 깨지 않는 것이 목표다.

### 깨질 수 있는 세 지점과 대응

| 위험 | 대응 |
| --- | --- |
| 팝오버를 **열 때 처음 만들면**(lazy) `self.datetime_input`이 없어 단축키가 죽는다 | 위젯은 지금처럼 **`__init__`에서 전부 생성**한다. 팝오버는 담는 그릇일 뿐 |
| 팝오버를 `QDialog`/`Qt.Popup` 같은 **별도 최상위 창**으로 만들면 포커스가 편집기 밖으로 나가 `WidgetWithChildrenShortcut`이 끊긴다 | 팝오버는 **MemoEditor의 자식 `QFrame`** + `raise_()` |
| `reminder_details`를 없애면 그 위에 걸린 **`Ctrl+Enter` 알림 저장**의 부모가 사라진다 (`editor.py:318`) | `Ctrl+Enter` 단축키도 **MemoEditor로 옮긴다** |

추가로, 접힌 상태에서 눌렀을 때 **아무 일도 안 일어난 것처럼 보이면 안 된다.**

- 알림 칩 라벨을 즉시 `오늘 18:30`으로 바꾼다
- 상태줄에 `1시간 뒤 알림을 저장했습니다.` 한 줄
- 이미 저장된 알림이 있으면 칩이 파랑으로 강조된다

### 완료 기준 (테스트로 못 박을 것)

새 파일 `test_memo_property_bar.py`에 아래를 그대로 넣는다.

1. 팝오버가 **닫힌** 상태 + 본문에 커서 → `Alt+1` → 1시간 뒤 알림이 DB에 저장되고 칩 라벨이 시각으로 바뀐다
2. 팝오버가 **열린** 상태 → `Alt+1` → 같은 결과 (중복 저장 없음)
3. **집중 모드(F11)** 에서 → 같은 결과
4. **별도 편집창**(`StandaloneMemoEditorWindow`) 에서 → 같은 결과
5. **포스트잇 창**에서 → 같은 결과 (같은 편집기를 쓴다)
6. 보조키를 `Shift` / `Ctrl+Shift`로 바꾼 뒤 `reload_shortcuts()` → 새 조합으로 같은 결과
7. `Ctrl+Enter`(알림 저장) 가 팝오버가 닫힌 상태에서도 동작
8. 본문에서 **평범하게 `1`을 타이핑**해도 알림이 저장되지 않는다 (보조키 없는 입력 보호)

## 5. 테스트 계획

| 무엇 | 어떻게 |
| --- | --- |
| 새 기능 | `test_memo_property_bar.py` (4번의 8개 + 칩 라벨·팝오버 열고 닫기·Esc) |
| 부동 서식 막대 | `test_memo_format_bar.py` (선택 시 표시, 위치가 내용을 안 가림, Esc 닫기, 제목1~4 적용) |
| 회귀 | 전체 753개. 위젯 이름을 유지했으므로 **실패 0이 기준**. 실패하면 이름을 바꾼 것이니 되돌린다 |
| 레이아웃 | `test_ui_responsive.py`에 780px·900px·1080px·1920px 네 폭 추가 |
| 실기기 | Windows 100%·125%·150% 배율에서 팝오버 위치·부동 막대 잘림 확인. **이번 진단에서 못 한 Alt+드래그도 이때 함께** |

**빠뜨리기 쉬운 검사** — 이번 진단에서 기존 테스트가 놓친 경로들이다. 새 테스트에 꼭 넣는다.

- 제목은 **빈 줄에서 시작**하는 경로로도 검사한다 (`/` 메뉴, `# ` 마크다운, 우클릭 세 경로 전부)
- 토글 묶기는 **비연속 선택**과 **단일 블록**으로도 검사한다
- 단축키는 `keyPressEvent` 직접 호출이 아니라 **`QTest.keyClick`** 으로 검사한다 (QShortcut이 먼저 가로채는 상황을 재현해야 한다 — 결함 D가 이래서 안 잡혔다)

## 6. 위험

| 위험 | 크기 | 대비 |
| --- | --- | --- |
| 팝오버로 옮기면서 시그널 연결이 끊긴다 | 높음 | 위젯 생성·연결 코드를 **건드리지 않고 부모만** 바꾼다. `setParent()` 는 시그널을 끊지 않는다 |
| 단축키가 조용히 죽는다 | 높음 | 4번 계약의 8개 테스트. `QTest.keyClick` 으로 |
| 회귀 753개가 대량 실패 | 중간 | 위젯 이름 유지. Stage마다 전체 회귀를 돌리고, 실패가 5개를 넘으면 그 Stage를 되돌린다 |
| 익숙한 배치가 바뀌어 불편하다 | 중간 | `memo_editor_layout=classic` 으로 한 달간 되돌릴 수 있게 |
| 좁은 창에서 팝오버가 화면 밖으로 나간다 | 낮음 | 팝오버 위치를 편집 영역 안으로 clamp (`BlockActionBar.sync()` 가 이미 쓰는 방식) |
