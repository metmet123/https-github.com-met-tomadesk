- 이 세션은 리눅스 컨테이너에서 돌고, 사용자 PC에 셸이 없다. 그래서 pytest는 리눅스에서 실행했다.

- 토마펫 스프라이트(`spritesheet.webp`, 2.5MB)는 옮기지 않아 해당 테스트는 자산 없음으로 실패한다.

## 3. 발견한 결함

### 🔴 결함 A — 빈 줄에 제목1~4를 주면 제목 글씨가 적용되지 않는다

**실제 화면에서 확인함.**

재현
1. 메모 본문에서 빈 줄에 커서를 두고 `/` → `제목1` 선택
2. 바로 글자를 입력한다

결과
- 입력한 글자가 **본문과 똑같은 10pt 보통 글씨**로 나온다. 도구막대 `크기`도 10 그대로.
- 같은 줄에 글자를 먼저 쓰고 나서 제목1을 주면 정상적으로 22pt 굵게 된다.

원인
- `alert_notes/rich_memo_edit.py` `apply_heading()`
  ```python
  block_cursor.movePosition(EndOfBlock, KeepAnchor)
  char_format = QTextCharFormat(); char_format.setFontPointSize(point_size) ...
  block_cursor.setCharFormat(char_format)
  ```
  **빈 블록은 선택 범위 길이가 0**이라 `setCharFormat`이 아무 글자에도 닿지 않는다.
  그리고 이어 입력될 글자에 쓸 `setCurrentCharFormat()`을 부르지 않는다.
  (바로 아래 `apply_body_style()`에는 `self.setCurrentCharFormat(...)`이 있다. 제목 쪽에만 빠져 있다.)
- 기존 `test_memo_phase3_editing.py`는 `self.editor("H1\nintro\n...")`처럼 **항상 글자가 있는 줄**에 제목을 적용해서 이 경로를 지나가지 않는다.

프로브 결과(제목1~4 전부 동일)

```
제목1: 크기=(0.0, 400)  level=1     ← 0.0 = 기본(본문) 크기, 400 = 보통 굵기
제목2: 크기=(0.0, 400)  level=2
제목3: 크기=(0.0, 400)  level=3
제목4: 크기=(0.0, 400)  level=4
비교) 글자 먼저 → 제목1: 크기=(22.0, 700)
```

### 🔴 결함 B — 그렇게 만든 제목은 메모를 다시 열면 제목이 아니게 되고, 접어 뒀다면 `▶` 기호만 본문에 남는다

**자동 재현으로 확인. 실행 파일 재시작 확인은 아직 못 함(9번 참고).**

재현
1. 결함 A대로 빈 줄에 제목1을 주고 글자를 입력
2. 저장 후 메모를 다시 연다

결과

```
저장 전 : heading_level = 1
재열기  : heading_level = 0,  글자 크기 10.5pt(본문)
```

접은 상태로 저장했다면 더 나쁘다.

```
재열기 텍스트 : '▶ 빈 줄에 제목1'      ← ▶ 가 그냥 본문 글자로 남는다
재열기 level  : 0
펴기 시도     : fold_heading() → False   ← 화살표도 없고 펼 수도 없다
모두 펴기     : toggle_all_folds() → 대상 아님, 아무 일도 없음
```

즉 **접어 둔 하위 내용이 열 수 없는 상태로 묻힐 수 있다.**
메모 목록의 `내용` 미리보기에도 `▶` 기호가 그대로 노출된다(실제 화면 확인).

원인
- WORK_LOG(1485줄)에 적힌 대로 Qt 블록 property는 HTML로 직렬화되지 않는다. 그래서 `heading_level()`은 재열기 후 **글자 크기로 제목 단계를 되짚는다.**
- 결함 A 때문에 그 글자 크기가 본문과 같아서 되짚기가 실패한다.
- 반면 `▶ ` 표시 마커는 문서 본문 글자라 그대로 살아남는다.

비교군(정상 경로)은 문제없다: 글자를 먼저 쓰고 제목1 → 접기 → 재열기 시 level 1 유지, 접힘 상태 유지, 펴기 정상.

### 🔴 결함 C — 떨어진 블록을 "토글로 묶기" 하면 Ctrl+Z가 되돌리지 못하고, 누를수록 빈 줄이 늘어난다

**실제 화면에서 확인함.** Phase 2 완료 기준("각 명령을 한 번의 Undo로 되돌릴 수 있어야 한다") 위반.

재현
1. `Alt+클릭`으로 떨어진 블록 2개 선택
2. 우클릭 → `블록` → `토글로 묶기`
3. `Ctrl+Z`

결과
- 토글은 그대로 남는다.
- 대신 **빈 줄이 하나 생긴다.** Ctrl+Z를 누를 때마다 빈 줄이 계속 늘어난다.

프로브로 경계를 좁힌 결과

| 선택 | 결과 |
| --- | --- |
| 연속 2줄 (뒤에 자식이 딸려 들어감) | 정상. 1회 Undo로 복원 |
| 단일 블록 1개 | **깨짐** — 빈 안내 줄이 생기고 Undo 불능 |
| 떨어진 2개 | **깨짐** — 토글 2개 + 빈 줄이 계속 증식 |

```
전      : ['가', '나', '다', '라']
묶기 후 : ['가', '▾ 나', '', '다', '▾ 라', '']
Undo 1회: ['가', '▾ 나', '', '', '다', '▾ 라', '']
Undo 2회: ['가', '▾ 나', '', '', '', '다', '▾ 라', '']
Undo 3회: ['가', '▾ 나', '', '', '', '', '다', '▾ 라', '']
```

원인(추정)
- `block_commands.py` `command_group_toggle()`은 `beginEditBlock/endEditBlock`으로 잘 묶여 있다.
- 그런데 `execute()`가 그 묶음이 **끝난 뒤** `editor._refresh_structure()`를 부르고, 거기서 `_ensure_toggle_children()`이 "빈 토글입니다" 안내 자식 줄을 **별도 편집**으로 집어넣는다.
- 그래서 Undo가 안내 줄 보충과 서로 맞물려 되풀이된다. 안내 줄이 필요 없는 경우(뒤에 자식이 바로 붙는 연속 선택)만 우연히 정상으로 보인다.
- `test_memo_phase2_blocks.py`의 묶기 검사는 그 "연속" 경우만 지나간다.

### 🟠 결함 D — Esc로 블록 선택이 풀리지 않는다 (다른 곳을 클릭해도 안 풀린다)

**실제 화면에서 확인함.** Phase 2 명세("Esc로 선택과 막대를 함께 닫는다") 위반.

재현·결과
- `Alt+클릭` 후 `Esc` → 여전히 `N개 선택`, 부동 막대 그대로.
- 편집 영역 빈 곳을 그냥 클릭해도 풀리지 않는다.
- 풀린 줄 알고 다시 `Alt+클릭`하면 **선택이 계속 쌓인다.** (1개 → Esc → Alt+클릭 → `3개 선택`)
- 사실상 선택을 푸는 방법이 **다른 메모로 옮겼다 오는 것**밖에 없다.

원인
- `alert_notes/panel.py:146`
  ```python
  self.back_shortcut = QShortcut(QKeySequence(Qt.Key.Key_Escape), self.editor)
  self.back_shortcut.setContext(Qt.ShortcutContext.WidgetWithChildrenShortcut)
  self.back_shortcut.activated.connect(self.go_back)
  ```
  Qt는 **QShortcut을 위젯의 `keyPressEvent`보다 먼저** 처리한다. 그래서
  `rich_memo_edit.keyPressEvent`의
  ```python
  if event.key() == Qt.Key.Key_Escape and self.block_selection.count():
      self.block_selection.clear(); return
  ```
  가 절대 실행되지 않는다.
- Phase 3에서 넣은 "기존 단축키와의 충돌 검사"가 이 조합을 걸러내지 못했다.
- 자동 테스트는 `keyPressEvent`를 직접 호출해서 통과한다. 실제 키보드에서는 QShortcut이 먼저 가로챈다 — **자동 테스트와 실사용이 갈리는 지점.**

### 🟡 결함 E — 부동 도구막대가 윗줄 내용을 가린다

**실제 화면에서 확인함.**

- 막대는 선택한 **첫 블록 바로 위**에 그려진다. 그래서 위쪽 1~2줄이 막대에 덮인다.
- 문서 위쪽을 선택하면 첫 줄(메모 맨 앞 내용)이 계속 가려진 채로 있다.
- `block_action_bar.py sync()`가 `위 공간이 4px 이상이면 무조건 위`로 두기 때문이다. 가려질 내용이 있는지는 보지 않는다.
- 결함 D(선택이 안 풀림) 때문에 막대가 계속 떠 있어서 체감이 훨씬 크다. **제보하신 "선택·도구막대 문제"의 실체는 D + E 조합으로 보인다.**

## 7. 결함 요약 (고칠 순서 제안)

| # | 결함 | 심각도 | 확인 방법 |
| --- | --- | --- | --- |
| A | 빈 줄에 제목1~4 → 제목 글씨 안 먹음 | 🔴 높음 | 실제 화면 |
| B | 그 제목이 재열기 후 소실, `▶` 잔존, 접힌 내용 못 펼침 | 🔴 높음 | 자동 재현 |

## 8. 기존 테스트가 왜 못 잡았나

- 제목 검사는 전부 **글자가 있는 줄**에 제목을 적용한다. 빈 줄 경로가 없다.
- 토글 묶기 검사는 **연속 선택**만 쓴다. 안내 자식 줄이 생기는 경우가 없다.
- 단축키 검사는 `keyPressEvent`를 **직접 호출**한다. 실제 키 입력에서 QShortcut이 먼저 가로채는 상황을 재현하지 않는다.
- 부동 막대 검사는 위치·잘림만 본다. **무엇을 가리는지**는 보지 않는다.
