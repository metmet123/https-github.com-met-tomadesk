## 2. Phase 4가 만든 새 전제

계획에 직접 영향을 주는 세 가지.

**① 목차 패널이 편집 칸의 가로를 먹는다.**
`editor.py:222` — `OutlinePanel`이 본문과 **나란히**(`body_host`의 가로 배치) 들어간다. 기본은 숨김이고 제목 줄의 `목차` 버튼으로 연다. 편집 칸이 좁으면 버튼이 아예 비활성화된다(`_set_outline_visible`의 `roomy`).
→ **편집 칸을 넓히는 일(Stage 1)의 값이 올라갔다.** 지금 편집 칸은 최대화해도 587px이라, 목차를 열면 본문이 더 좁아진다.

**② 하단 예약 띠가 이미 둘 있다.**

| 띠 | 언제 | 높이 |
| --- | --- | --- |
| `BlockActionBar` | 블록 선택 중 | 38 + 4px |
| `CharacterRangeActionBar` | 글자 구간 선택 중 | 38 + 4px |

`_sync_selection_bar_height()`가 둘을 배타적으로 처리한다(글자 구간이 우선).
→ 여기에 서식 막대를 **세 번째 띠로** 만들면 안 된다. 같은 자리에 **하나로 통합**한다.

**③ 제목 줄 버튼이 늘었다.** 가져오기·백업 / **목차** / ◀ / ⛶ 네 개다. 속성 칩 줄을 넣을 때 제목 줄이 더 붐비지 않도록 주의한다.

## 3. 설계 원칙 (v1에서 유지 + 하나 추가)

1. **자리를 옮기는 것이지, 없애는 것이 아니다.** 위젯 객체와 이름(`self.datetime_input`, `self.quick_buttons`, `self.reminder_save_button` …)은 그대로 두고 **부모만 바꾼다.** 기존 테스트가 이 이름들을 88회 참조한다.
2. **보이는 것과 살아 있는 것을 분리한다.** 팝오버가 닫혀 있어도 값·시그널·단축키는 동작한다.
3. **팝오버는 최상위 창이 아니라 편집기의 자식 위젯이다.** 포커스가 나가면 `WidgetWithChildrenShortcut` 단축키가 전부 끊긴다.
4. **(신규) 도구는 본문 글자 위에 겹치지 않는다.** Phase 4가 세운 원칙이다. 새로 만드는 모든 막대·띠가 이 원칙을 따른다.

## 4. 결정 질문 2에 대한 답 — 두 번 바뀌어 최종 확정

**경위**
1. 아침: "본문을 **덮는(overlay)**" 쪽을 권함. 근거는 "이미 `BlockActionBar`가 오버레이이니 일관성이 맞다".
2. 낮: **그 사이 `BlockActionBar`가 오버레이를 버린 것**을 확인 → 근거가 사라져 **철회**. 대신 "하단 예약 띠 하나로" 권함.

```python
class BlockActionBar(QFrame):
    """Selection commands in reserved editor space, never over document text."""
```

3. 실기 렌더로 세 안을 비교한 뒤 **최종 확정**: 부동의 장점(손이 그 자리에 있다)을 버리지 않으면서 가림 문제를 0으로 만드는 절충안.

**(2026-09-14 확정) 서식 도구는 작게 만들어 선택한 줄의 오른쪽 여백에 붙이고, 자리가 없으면 위아래로 밀지 말고 하단 예약 띠로 내려보낸다.**

실제 편집기에 시제품을 붙여 재 본 값이다(편집 칸 930px, 본문 폭 874px).

| 막대 | 폭 | 오른쪽에 붙는 조건 | 좁은 칸(644px) |
| --- | --- | --- | --- |
| 전체(`B I U S 제목1~4 본문 색`) | **536px** | 줄 끝 328px 이내 (한글 ~20자) | **불가능** |
| **컴팩트(`B I U S · 서식 ▾`)** | **240px** | 줄 끝 624px 이내 (~40자) | 줄 끝 394px 이내 |

그리고 **긴 문단은 줄바꿈된다**. 붙일 자리는 논리적 줄 끝이 아니라 **마지막으로 보이는 줄의 끝**이라, 실제로는 대부분 짧다. 930px 칸에서 두 줄짜리 긴 문단을 골라도 끝이 221px여서 여유 있게 들어갔다.
→ **되돌아갈 일(하단 띠로 내려가는 경우)이 생각보다 드물다.** 재현된 것은 좁은 칸(644px) + 화면을 거의 채운 줄뿐이었다.

배치 규칙(그대로 구현하면 된다):

```python
GAP, MARGIN = 10, 6

end  = QTextCursor(cursor); end.setPosition(cursor.selectionEnd())
tail = editor.cursorRect(end)            # 마지막으로 보이는 줄의 끝
view = editor.viewport().width()

if tail.right() + GAP + bar.width() + MARGIN <= view:
    bar.move(tail.right() + GAP,
             tail.top() + (tail.height() - bar.height()) // 2)   # 줄 오른쪽 여백
else:
    show_in_reserved_strip()             # 위아래로 밀지 않는다
```

**이 규칙의 값어치**: 본문 글자를 가리는 경우가 **0**이 된다. 부동 막대의 장점(손이 이미 그 자리에 있다)은 대부분의 경우 그대로 얻고, 안 될 때는 이미 블록 선택·글자 구간 선택이 쓰는 그 자리로 떨어진다. **새 자리를 만들지 않는다.**

`서식 ▾`는 제목1~4 · 색 · 글씨체 · 크기 · 줄 간격을 담는 드롭다운이다. 기능은 하나도 빠지지 않는다.

```
┌─────────────────────────────┐
│ 제목 · 목차 · ◀ · ⛶          │  ← 1줄
│ 🔔 알림  📌 D-Day  🎨 색  ⌨   │  ← 1줄 (속성 칩)
│                             │
│        본  문                │
│                             │
│─────────────────────────────│
│ [선택 도구 띠 — 필요할 때만]    │  ← 블록/글자/서식이 한 자리를 나눠 쓴다
└─────────────────────────────┘
│ 서식 ▾ · ● 자동 저장됨 · 휴지통 │  ← 1줄
```

- **평소**: 띠가 없다. 본문이 최대.
- **블록 선택 중**: `N개 블록 선택 · ↑ ↓ 복사 작업▾ ×` (지금 그대로)
- **글자 구간 선택 중**: `N개 글자 구간 · 연동 해제 ×` (지금 그대로)
- **평범한 글자 선택 중**: `B I U S · 제목1~4 · 본문 · 색 ×` ← **새로 추가할 것**
- 세 상태는 **배타적**이다. 높이는 언제나 42px 하나뿐이다.

이 방식의 장점: ① 세 번째 막대가 안 생긴다 ② 사용자가 "선택하면 아래에 도구가 나온다"를 **한 번만 배우면 된다** ③ 본문 위에 아무것도 안 뜬다 ④ 상단 서식 2줄(74px)을 없앨 명분이 생긴다.

`서식 ▾` 버튼은 **선택이 없을 때** 쓰는 나머지(글씨체·크기·줄 간격·서식1~3·기본값·단축키·이미지)를 담아 같은 띠에 펼친다. 역시 42px, 본문을 밀지 않는다.

## 5. 단계

### Stage 1 — 레이아웃 (가장 싸고, 목차 때문에 값이 올라갔다)

`alert_notes/panel.py`
- `setStretchFactor(1, 1)` — 지금 `0:0:1`이라 창을 넓혀도 **오늘 요약만** 늘어난다.
- `editor_remainder.setMaximumWidth(360)`.
- 기본 비율 `700:640:560` → `520:780:400`.
- 오늘 요약이 D-Day·일정·알림 **셋 다 비면 자동 접기**(펼치기 손잡이만).

`alert_notes/editor.py`
- `content_edit.setMinimumHeight(180 → 320)` (`editor.py:212`).
- `TWO_COLUMN_WIDTH`는 **900 그대로.** 주석의 근거(440+413+26=879)가 타당하다.

**완료 기준**: 1920×1010에서 본문 554 → 684px. 편집 칸 930px 이상이 되어 **목차를 열어도 본문이 좁아지지 않는다.**
**분량**: 1~2시간.

### Stage 2 — 속성 칩 줄 (~170px)

**새 파일** `alert_notes/note_property_bar.py`
- `PropertyChipBar(QWidget)` — 칩 한 줄. 칩마다 id·아이콘·**값 요약 라벨**·열 패널.
- `PropertyPopover(QFrame)` — **MemoEditor의 자식**. `raise_()`로 띄우고 `hide()`로 닫는다. `QDialog`/`Qt.Popup` 금지(원칙 3).

**`editor.py` 변경** — `reminder_card` · `hotkey_card` · `below_host`(서식1~3·항상 위·포스트잇) · `actions_host`(입력 잠금·색·투명)를 팝오버 페이지로 **재부모화.** 생성 코드는 손대지 않는다.
아래 한 줄에 남는 것: `서식 ▾` · `saved_status` · `manual_save_button` · `delete_button`.

**칩 라벨**

| 칩 | 값 없음 | 값 있음 |
| --- | --- | --- |
| 알림 | `알림` (회색) | `오늘 18:30` (파랑) |
| D-Day | `D-Day` | `D-28 제출 마감` |
| 색 | 색 점 | 색 점 + `투명 30%` |
| 단축키 | `단축키` | `Ctrl+Alt+M` |
| 그 밖 | `⋯` | 켜진 항목 수 배지 |

**Esc 연결**: `panel._escape_editor_or_go_back()`의 단계 목록 **맨 앞**에 "속성 팝오버가 열려 있으면 닫기"를 넣는다. 이미 있는 구조라 한 줄이다.

**분량**: 1~2일.

### Stage 3 — 문자 서식 막대 (~74px)

**새 클래스** `TextFormatRangeBar` — 두 가지 모습을 한 클래스가 가진다.

| 모습 | 언제 | 내용 | 스타일 |
| --- | --- | --- | --- |
| **떠 있는 컴팩트 막대** (240px) | 줄 오른쪽에 자리가 있을 때 | `B I U S · 서식 ▾` | 어두운 알약 (`#172033`, radius 9) |
| **하단 예약 띠** (38+4px) | 자리가 없을 때 | `글자 선택 · B I U S · 제목1~4 · 본문 · 색 · ×` | 기존 두 띠와 동일 (`#f8fafc`, border-top `#cbd5e1`) |

- 배치는 4번의 규칙 그대로. **위아래로 미는 분기는 만들지 않는다.**
- 띠 모습일 때는 `_sync_selection_bar_height()`의 배타 목록에 **셋째 상태**로 들어간다. 우선순위: 글자 구간 > 블록 > 평범한 선택.
- 트리거: `selectionChanged` + **마우스 버튼을 뗀 뒤**. 드래그 중에는 뜨지 않는다.
- 스크롤·창 크기 변경 시 다시 계산한다(`BlockActionBar.place()`와 같은 시점).
- 상단 서식 2줄 제거. 나머지(글씨체·크기·줄 간격·서식1~3·기본값·단축키·이미지)는 아래 한 줄의 `서식 ▾`로.
- `format_toolbar` 이름과 공개 메서드(`reload_shortcuts`, `move_presets_to`, `set_auxiliary_button`)는 유지(테스트 16회 참조).

**완료 기준**
- 글자를 고르면 막대가 뜨고 `Esc`로 닫힌다(`_escape_editor_or_go_back`의 단계에 추가).
- **어떤 선택에서도 본문 글자를 가리지 않는다.** 검사 방법: 선택 직후 막대의 `geometry()`가 문서의 어느 글자 사각형과도 겹치지 않는지 확인.
- 두 모습이 배타적이고, 띠 모습일 때만 본문 높이가 42px 줄어든다.

**분량**: 1~1.5일.

### Stage 4 — 좁은 창

- 1080px 미만: 목록은 **손잡이만 남는 서랍**, 오늘 요약 숨김, 칩은 앞 3개 + `⋯`.
- 목차 버튼 비활성 기준(`roomy`)을 칩 줄과 함께 다시 잡는다.
- `test_ui_responsive.py`에 780·900·1080·1920 네 폭 추가.

**분량**: 반나절.

### Stage 5 — 발견 가능성

- **설명서 한 장 추가**: 속성 칩 / 선택 도구 띠 / 서식 접기 / 집중 모드 / Alt+클릭 블록 선택 / **목차와 블록 링크**(Phase 4). 현재 검색 결과 0건이다.
- **설정 추가**: "새 메모는 항상 집중 모드로 열기".
- **제목 단축키 등록**: `Ctrl+Shift+1~4`. `insert_menu.py`의 `HEADING_ITEMS` 네 줄에 `shortcut` 값만 채우면 `install_insert_shortcuts`가 알아서 건다.

## 7. 빠른 알림 등록 단축키 계약 ★ (v1과 동일, 현재 코드로 재확인)

> 요구: **속성이 접혀 있어도 Alt+Q / Alt+` / Alt+1~6 / Alt+W 가 그대로 동작해야 한다.**

현재 코드(재확인함):

```python
# editor.py:1018
self.time_shortcuts = bind_time_shortcuts(self, self.store, self._quick_reminder)

# editor.py:953
def _quick_reminder(self, minutes, _label=""):
    self.datetime_input.set_datetime(datetime.now() + timedelta(minutes=minutes))
    self._quick_time_active = False
    self._save_reminder()
```

단축키는 **MemoEditor 자신**에 `WidgetWithChildrenShortcut`으로 걸려 있고, `_quick_reminder`는 위젯이 보이는지와 무관하게 값을 넣고 바로 저장한다. **지금도 알림 카드를 접은 채 동작한다.**

| 깨질 수 있는 지점 | 대응 |
| --- | --- |
| 팝오버를 **열 때 처음 만들면**(lazy) `self.datetime_input`이 없어 단축키가 죽는다 | 위젯은 `__init__`에서 전부 생성. 팝오버는 담는 그릇만 |
| 팝오버가 **별도 최상위 창**이면 포커스가 편집기 밖으로 나가 `WidgetWithChildrenShortcut`이 끊긴다 | MemoEditor의 **자식 QFrame** + `raise_()` |
| `reminder_details`를 없애면 `Ctrl+Enter` 알림 저장의 부모가 사라진다 (`editor.py:339` — **여전히 `reminder_details`에 걸려 있다**) | `Ctrl+Enter`도 **MemoEditor로 옮긴다** |

피드백(접힌 상태에서 눌렀을 때 아무 일도 안 난 것처럼 보이면 안 된다):
알림 칩 라벨 즉시 `오늘 18:30`으로 · 상태줄에 `1시간 뒤 알림을 저장했습니다.` · 값이 있으면 칩 파랑 강조.

### 완료 기준 — `test_memo_property_bar.py`에 그대로 넣을 것

1. 팝오버 **닫힌** 상태 + 본문 커서 → `Alt+1` → 1시간 뒤 알림 저장 + 칩 라벨이 시각으로
2. 팝오버 **열린** 상태 → 같은 결과, 중복 저장 없음
3. **집중 모드(F11)** 에서 → 같은 결과
4. **별도 편집창**(`StandaloneMemoEditorWindow`) 에서 → 같은 결과
5. **포스트잇 창**에서 → 같은 결과
6. 보조키를 `Shift`/`Ctrl+Shift`로 바꾸고 `reload_shortcuts()` → 새 조합으로 같은 결과
7. `Ctrl+Enter`(알림 저장)가 팝오버 닫힌 상태에서 동작
8. 본문에서 **평범하게 `1`을 타이핑**해도 알림이 저장되지 않는다
