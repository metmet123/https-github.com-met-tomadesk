# TomaDesk 메모 편집 — 사용성·UI 분석

- 작성일: 2026-09-14
- 바탕: 같은 날 진행한 Phase 1~3 진단 (코드 검토 + 회귀 재실행 + 실제 화면 조작)
- 성격: **버그가 아니라 "되긴 되는데 쓰기 불편한 것"**을 모았다. 코드는 수정하지 않았다.

## 0. 한 줄 요약

기능은 Notion급으로 붙었는데, **기능을 꺼내 쓰는 길(진입 경로)과 빠져나오는 길(취소·해제)이 기능 수를 못 따라갔다.**
아래 11개 중 U1~U4가 실제 조작에서 가장 크게 걸린 것이다.

---

## U1. 제목 만들기 — 사람이 자연스럽게 하는 순서가 전부 막혀 있다 🔴

진단서의 결함 A·B는 "빈 줄에 제목을 주면 안 먹는다"였다. 사용성 관점에서 더 중요한 사실은,
**제목을 만드는 정상 경로가 세 개인데 셋 다 빈 줄에서 시작한다**는 점이다.

| 경로 | 실제로 되나 |
| --- | --- |
| 줄 앞에 `# ` + 스페이스 (마크다운) | ❌ 제목 글씨 안 먹음 |
| `/` 메뉴 → 제목1 | ❌ 안 먹음 |
| 우클릭 → 블록 변환 → 제목 1 | ❌ (빈 줄에서) 안 먹음 |
| **글자를 먼저 다 쓰고** 줄을 잡아 제목 지정 | ✅ 됨 |

```
'# '    → 제목1: 크기=0.0 굵기=400 level=1 재열기level=0
'## '   → 제목2: 크기=0.0 굵기=400 level=2 재열기level=0
'### '  → 제목3: 크기=0.0 굵기=400 level=3 재열기level=0
'#### ' → 제목4: 크기=0.0 굵기=400 level=4 재열기level=0
```

즉 **유일하게 동작하는 순서가 가장 부자연스러운 순서**다. 메모를 쓰는 사람은 제목을 먼저 선언하고 내용을 채운다.
고칠 때 "빈 블록 예외 처리"로 보지 말고 **"제목을 먼저 지정하고 입력하는 흐름"을 1급 경로로 놓고** 설계하시길 권한다.

> 참고: `keyPressEvent`의 Enter 처리는 이미 `setCurrentCharFormat()`을 제대로 부른다(3227줄).
> `apply_heading()`에만 그 짝이 빠져 있다. 같은 사람이 같은 파일에 두 방식을 썼다는 뜻이니,
> **"블록 유형을 바꾸면 이어 칠 글자의 서식도 함께 정한다"를 한 군데로 모으는 것**이 재발 방지책이다.

**부수 문제**: 제목1~4만 단축키가 없다.

| 블록 | 단축키 |
| --- | --- |
| 체크리스트 | Ctrl+Shift+4 |
| 글머리표 | Ctrl+Shift+5 |
| 토글 | Ctrl+Shift+7 |
| 코드 줄 | Ctrl+Shift+8 |
| 페이지 | Ctrl+Shift+9 |
| **본문** | **Ctrl+Shift+0** |
| **제목1~4** | **없음** |

본문으로 되돌리는 키는 있는데 제목으로 가는 키가 없다. Notion은 Ctrl+Shift+1~3이다.
서식 도구막대에도 제목 버튼이 없다(접기 버튼은 있다). 가장 많이 쓰는 블록이 가장 찾기 어렵다.

## U2. 블록 선택을 "빠져나올 길"이 없다 🔴

- `Alt+클릭`으로 블록을 고르면 **Esc로도, 딴 데를 클릭해도 선택이 안 풀린다.**
  (원인은 진단서 결함 D — `panel.py:146`의 `Esc → go_back` QShortcut이 먼저 가로챈다)
- 풀린 줄 알고 `Alt+클릭`을 또 하면 계속 쌓인다. 실제로 "1개 선택 → Esc → Alt+클릭 → **3개 선택**"이 나왔다.
- 결국 선택을 푸는 방법이 **다른 메모로 갔다 오는 것**뿐이다.

사용성 원칙으로 보면 이건 "모드에 들어갔는데 나오는 문이 없는" 상태다. 최소한 세 가지가 다 있어야 한다.

1. `Esc`
2. 선택 바깥 아무 데나 **평범한 클릭** (지금은 `mousePressEvent`에서 선택을 지우지 않는다)
3. 부동 막대의 **닫기(×)** — 지금은 없다

그리고 `Esc`처럼 "취소"를 뜻하는 키에 `go_back`(뒤로 가기)을 걸어 둔 것 자체를 다시 볼 만하다.
뒤로 가기는 `Alt+Left`가 관례인데, 이 앱에서는 `Alt+Left`가 이미 "접힌 구조에서 부모로 복귀"에 쓰이고 있다.
**Esc는 취소, 뒤로 가기는 다른 키**로 정리하는 편이 예측 가능하다.

## U3. 부동 도구막대 — 가리고, 안 사라지고, 절반만 있다 🟠

실제 화면에서 본 모습:

```
┌────────────────────────────────────────────┐
│ 2개 선택  ↑  ↓  −  +  복사  해제  삭제      │  ← 메모 첫 두 줄을 덮고 있다
├────────────────────────────────────────────┤
│ (가려진 줄)                                 │
│ (가려진 줄)                                 │
│ 하위B                                       │
```

**① 내용을 가린다** — 항상 "선택한 첫 블록의 바로 위"에 그린다(`block_action_bar.sync()`).
위 공간이 4px만 있으면 무조건 위로 올린다. 문서 위쪽을 선택하면 메모 맨 앞 줄이 계속 가려진다.
U2(안 풀림)와 겹쳐서 체감이 크다. → 선택 블록의 **오른쪽 여백**이나 편집 영역 **상단 고정 띠**로 옮기는 편이 안전하다.

**② 기호가 뜻을 안 알려 준다**

| 버튼 | 실제 뜻 | 읽히는 뜻 |
| --- | --- | --- |
| `−` `+` | 내어쓰기 / 들여쓰기 | 축소 / 확대, 또는 삭제 / 추가 |
| `해제` | 연동 기능 삭제(토글·제목·체크·링크 구조 해제) | 무엇을 해제하는지 불명 |

툴팁에는 정확히 적혀 있지만, 툴팁은 **마우스를 1초 올려야** 보인다. `⇤ ⇥` 같은 들여쓰기 기호나 짧은 글자 라벨이 낫다.

**③ 막대에 있는 명령이 7개뿐이다** — Phase 2가 내건 목표는 "마우스·키보드·버튼이 **같은** 블록 명령을 실행"인데,
막대에는 이동·들여쓰기·복사·해제·삭제만 있다. **독립 복제, 토글로 묶기, 본문·제목1~4 변환은 막대에 없다.**
그 명령들을 쓰려면 결국 우클릭 → 하위 메뉴 → 항목까지 **3단계**를 다시 내려가야 한다.
블록을 골라 놓고도 "고른 상태에서 할 수 있는 일"이 반쪽만 보이는 셈이다.

## U4. 같은 명령인데 경로마다 결과가 다르다 🟠

**들여쓰기**가 대표적이다.

| 경로 | 대상 |
| --- | --- |
| 부동 막대 `+` / 우클릭 → 블록 → 들여쓰기 | **선택한 블록 전부** |
| `Tab` 키 | **커서가 있는 한 줄만** (게다가 커서가 줄 맨 앞일 때만) |

`Tab`/`Shift+Tab`은 들여쓰기의 세계 공통 키다. Alt로 5개를 골라 놓고 Tab을 누르면
"5개가 들어갈 것"이라 기대하는데 한 줄만 들어간다. (`rich_memo_edit.py:3217` — `offset == 0` 조건까지 붙어 있어
줄 가운데서는 아예 안 먹는다.)

같은 성격의 불일치가 하나 더 있다.
서식 도구막대의 글머리표 버튼 툴팁은 **"글머리표 (Ctrl+Shift+L)"**이라고 안내하는데,
메모 편집창에 실제로 걸린 키는 **Ctrl+Shift+5**다. `Ctrl+Shift+L`은 **포스트잇 창에만** 걸려 있다
(`postit.py:565`). 버튼이 안 먹는 키를 가르쳐 주고 있다.

## U5. 구조 표시가 "본문 글자"로 저장된다 🟠

접힌 제목의 `▶ `, 토글의 `▾ `/`▸ `, 체크의 `☐ `는 그림이 아니라 **문서 안의 진짜 글자**다.
WORK_LOG 1485줄에 "Qt 블록 property가 HTML로 직렬화되지 않아 마커를 본문에 보존한다"고 적힌 그 선택의 대가다.

실제로 새는 자리를 확인했다.

- **메모 목록의 `내용` 미리보기**에 `▶`가 그대로 보인다 (`memo_list.py:822`가 `plain_text_from_content`를 쓴다)
- 제목이 인식되지 않는 상태가 되면 `▶ `는 **지울 수 없는 쓰레기 글자**로 남는다 (진단서 결함 B)
- 본문 Ctrl+F 검색, 엑셀 내보내기, 외부 앱 붙여넣기에도 같은 글자가 따라간다

당장 고칠 게 아니라면 최소한 **미리보기·검색·내보내기 세 길목에서 선행 마커를 걷어내는 한 줄**을 두는 편이 좋다.
근본적으로는 접힘 상태를 문서 글자가 아니라 **메모 행의 별도 칸(JSON 등)**에 두는 쪽이 맞다.

## U6. Alt 키가 과부하 🟡

| Alt 조합 | 기능 |
| --- | --- |
| Alt+클릭 / Alt+드래그 | 블록 추가 선택 |
| Alt+↑ / Alt+↓ | 블록 이동 |
| Alt+← / Alt+→ | 접힌 구조 복귀 / 진입 |
| Alt+C | 문자 서식 복사 / 적용 |
| Alt+7 / 8 / 9 | 검정 / 빨강 / 파랑 |
| Alt+Q, `, 1~6, W | 알림 시간 (기본 보조키가 Alt) |

한 손가락에 여섯 종류가 걸려 있다. 실제 충돌은 없지만 **외울 수 없고, 오타가 바로 편집으로 이어진다**
(Alt+3을 잘못 누르면 알림이 걸린다). 알림 시간 보조키를 기본 `Ctrl+Shift`로 옮기거나,
편집 구조 조작은 Alt, 값 지정은 Ctrl+Shift로 **역할별 보조키 규칙**을 세우는 편이 낫다.

## U7. 우클릭 메뉴 — 한글·영어가 섞이고 깊다 🟡

실제 화면:

```
Undo        Ctrl+Z      ← Qt 표준 메뉴(영문)
Redo        Ctrl+Y
Cut         Ctrl+X
Copy        Ctrl+C
Paste       Ctrl+V
Delete
Select All  Ctrl+A
─────────────
블록          ▸          ← 직접 붙인 항목(한글)
블록 변환      ▸
연동 기능 삭제
붙여넣기 방식   ▸
```

- `createStandardContextMenu()`가 만든 항목은 Qt 기본 번역을 타서 **영문**이고, 뒤에 붙인 항목만 한글이다.
  한 메뉴에 두 언어가 섞여 있다. → 표준 메뉴 항목의 `setText()`를 한글로 덮어쓰면 끝난다.
- `Copy`(글자 복사)와 `블록 → 복사`(블록 복사)가 같은 메뉴에 나란히 있는데 이름이 구분되지 않는다.
- **붙여넣기가 두 군데**다. 위쪽 `Paste`와 아래쪽 `붙여넣기 방식 → 원본 서식 유지`가 같은 동작이다.
  Phase 3가 만든 세 방식은 하위 메뉴 안에 있어 존재를 모르면 못 찾는다.
- `블록 변환` 하위에 11개가 한 줄씩 나열된다. 본문/제목1~4와 목록류를 **구분선으로 나누면** 훑기 쉬워진다.

## U8. 새로 만든 기능이 설명서에 하나도 없다 🟠

프로그램 안 `설명서`(`user_manual_content.py`)에서 아래 낱말을 찾아본 결과 **0건**이다.

```
줄 간격 · 붙여넣기 · 블록 · 독립 복제 · 모두 접기 · 비연속
```

설명서는 2026-09-10에 완성됐고 Phase 1~3은 9-11 ~ 9-14에 들어갔다. 기능만 3주치 앞서 나갔다.

특히 **`Alt+클릭` 블록 선택은 어디에도 안내가 없다.** 화면에 힌트도 없다.
"있는 줄 모르면 영원히 못 쓰는 기능"이고, Phase 2 작업량 대부분이 여기에 들어갔다.
설명서 한 장 추가가 어렵다면, 최소한 **블록을 처음 드래그하거나 줄 손잡이에 마우스를 올렸을 때
"Alt+클릭으로 여러 줄 고르기" 한 줄 힌트**라도 띄우는 편이 값이 크다.

단축키 설정창(`노트 단축키 설정`)도 반쪽이다.

| 설정창에 있음 | 설정창에 없음 (고정) |
| --- | --- |
| 굵게·기울임·밑줄·취소선, 색 3종, 링크 열기, 접기 | Alt+↑↓ 이동, Alt+←→ 탐색, Alt+C, Ctrl+Shift+E, Ctrl+Shift+V, `/` 메뉴의 Ctrl+Shift+4·5·7·8·9 |

바꿀 수 있는 키와 못 바꾸는 키가 뒤섞여 있고, **전체 목록을 한눈에 보는 곳이 없다.**
설정창을 "바꾸는 곳"이자 "확인하는 곳"으로 만들어 고정 키도 회색으로 함께 보여 주면 좋겠다.

## U9. 되돌리기 모델이 셋인데 사용자는 하나로 안다 🟡

코드에는 되돌리기가 세 종류다.

1. Qt 문서 자체의 undo
2. 문서 + DB를 함께 묶는 복합 undo (`_undo_composite_or_document`)
3. 메모 목록 복제 전용 undo (`clone_undo_requested`)

사용자에게는 전부 `Ctrl+Z`다. 그래서 **어느 하나가 실패해도 사용자는 "Ctrl+Z가 고장났다"로만 느낀다.**
실제로 토글 묶기에서 그 일이 났다(진단서 결함 C): Ctrl+Z를 눌러도 토글은 그대로고 빈 줄만 늘었는데,
화면 어디에도 "되돌릴 게 없습니다" 같은 신호가 없었다.

- 되돌릴 대상이 없으면 상태줄에 한 줄 알려 주기
- 구조를 바꾸는 명령(묶기·변환·복제)은 **실행 직후 상태줄에 "토글로 묶었습니다 · Ctrl+Z로 되돌리기"** 표시

이 두 가지만 있어도 사용자가 "내가 잘못 누른 건지 앱이 안 먹는 건지"를 구분할 수 있다.

## U10. 빈 토글 안내문이 본문처럼 보인다 🟡

토글을 만들면 안쪽에 회색으로

```
빈 토글입니다. 클릭하거나 블록을 내부로 드래그하세요.
```

가 뜬다. 문서에 저장되지 않는 그림 글씨라 데이터는 안전하다. 다만

- 문장이 길어서 토글을 여러 개 만들면 화면이 안내문으로 덮인다 (실제로 토글 2개를 만드니 두 줄이 떴다)
- 존댓말 설명형이라 **본문 글자와 시각적 무게가 비슷하다**

`비었음 — 클릭해서 채우기` 정도로 줄이고 글자를 더 흐리게 하면 충분하다.

## U11. 메모 목록에서 두 번 클릭하면 이름 바꾸기로 빠진다 🟡

실제 조작 중 두 번 겪었다. 이미 선택된 메모 행을 다시 클릭하면(= 다시 열려는 의도)
제목 칸이 **이름 바꾸기 입력창**으로 바뀐다. Windows 탐색기와 같은 동작이지만,
여기서는 그 행이 "지금 편집 중인 메모"라서 다시 클릭하는 일이 훨씬 잦다.

`F2` 또는 우클릭 → 이름 바꾸기로만 진입시키는 편이 사고가 적다.

## 검증 범위 (이 분석의 한계)

- 실제 조작은 **메모 편집 화면 한 곳**에서 30여 분간 했다. 캘린더·단축키·포스트잇 화면은 보지 않았다.
- `Alt+드래그`는 원격 조작 도구가 수식키를 누른 채 드래그를 못 보내서 확인하지 못했다.
- 화면 배율 100%·최대화 창 한 조건에서만 봤다. 좁은 창(760px 이하)과 125%·150% 배율은 확인하지 못했다.
- 다른 사람이 쓰는 모습을 관찰한 것이 아니라, **한 사람(나)이 부딪힌 마찰**을 적은 것이다.
  U1·U2·U3은 제보 내용과 일치하므로 신뢰도가 높고, U6·U9·U10은 판단이 갈릴 수 있다.
