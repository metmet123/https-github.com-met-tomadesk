# 화면 글자 따기 3-2 — 새 메모·D-Day (2026-09-19)

## 사용법

1. 소스로 재실행하고 `Ctrl+Alt+O`로 영역을 인식한다. 기존 EXE는 갱신하지 않았다.
2. 결과창에서 오인식을 수정한다. 저장 대상은 최초 인식 원문이 아니라 **현재 편집한 본문**이다.
3. `메모로 만들기`를 누르면 확인창이 열린다. 첫 번째 빈 줄이 아닌 줄의 앞 120자를 제목 초안으로 쓰며, 제목은 수정할 수 있다. 본문은 전체를 보존한다.
4. 확인창의 `확인한 내용으로 새로 만들기`를 눌러야 저장된다. 취소/닫기는 아무것도 만들지 않는다. Enter의 기본 동작은 취소다.
5. 날짜가 인식되면 `D-Day로 만들기`가 표시된다. 여러 후보가 있으면 직접 하나를 선택한 다음 날짜·시간을 확인/수정하고 저장한다.
6. 날짜만 있고 시간이 없으면 **00:00이 초기값**임을 표시한다. OCR은 정확한 전사가 아니므로 실제 마감 시각을 확인한다. 필요하면 확인창에서 바꾼다.
7. `날짜 제안 숨기기` 또는 D-Day 확인창 취소는 해당 인식 결과의 제안을 숨긴다. 다음 `다시 인식`에서 새 제안을 받을 수 있다. 일반 메모로 만드는 것은 계속 가능하다.

저장 성공 후에는 해당 인식 결과를 다시 저장하지 않도록 두 생성 버튼을 비활성화한다. 다시 인식하면 새 결과로 저장할 수 있다. OCR 저장은 클립보드를 다시 복사하는 동작이 아니다.

## 날짜 해석 범위

- 기존 `alert_notes/ko_schedule_parser.py`를 수정하지 않고 재사용한다. 각 줄의 시작에 있는 `내일 오후 3시`, `2026-09-30 18:00`, `10/15` 등과 `마감일:`·`마감:`·`날짜:`·`일시:` 접두어 뒤를 읽는다.
- 문장 중간의 임의 숫자/날짜를 찾아 추측하지 않는다. 필요한 날짜가 제안되지 않으면 결과창에서 날짜를 새 줄의 시작으로 옮겨 확인할 수 있다.
- 시간만 있는 표현, 반복 일정, 잘못된 날짜는 제안하지 않는다. 기존 파서의 한국어 시간 관례와 연도 없는 날짜의 다음 해 해석을 그대로 사용하므로 확인창에서 실제 날짜를 검토한다.
- `내일` 같은 상대 날짜는 결과창에 인식 결과가 표시된 시점에 고정한다. 편집 중 자정이 지나도 후보가 저절로 하루 밀리지 않는다.
- 분석은 앞 20,000자/200줄, 한 줄 1,000자 이하, 서로 다른 후보 최대 10개로 제한한다. **저장 본문은 이 제한으로 자르지 않는다.**

## 보호 범위

- 기존 메모를 덮어쓰거나 자동 저장하지 않는다. 메모 목록/달력/요약만 갱신하고 활성 편집기는 다시 불러오지 않는다. 검색/분류 필터는 유지하므로 새 메모가 안 보이면 해당 필터를 확인한다.
- 메모와 D-Day 필드를 하나의 INSERT·트랜잭션으로 생성한다. 생성 실패 시 빈 메모만 남는 중간 상태를 만들지 않으며 재시도할 수 있다. DB 스키마는 바꾸지 않았다.
- 개별 D-Day 알림은 `d_day_alert=0`이며 reminder/schedule 레코드를 추가하지 않는다. **기존 앱 설정의 당일 요약 알림은 그대로 적용된다.** 그 설정을 임의로 끄지 않는다.
- 저장 후 목록 갱신만 실패하면 ‘저장됐지만 갱신 실패’로 알리고 재삽입하지 않는다.
- HTML 소스처럼 보이는 인식 글자도 일반 텍스트로 보존한다. 외부 이미지/링크를 HTML로 해석하지 않도록 기존 저장 포맷에 맞게 안전하게 담는다.
- 화면 전송/외부 AI 호출/사용자 DB 대상 시험/EXE 변경은 없다. 자동 검사는 임시 DB와 생성한 이미지로만 수행했다.
