# 메모 정리 — 로컬 기능과 외부 AI 설정

2026-09-19 구현. 이번 버전은 외부 AI 호출·API 키·네트워크 전송을 포함하지 않는다.

## 사용 방법

1. 메모·일정 화면의 **메모 정리** 탭을 연다.
2. **수집함·검토**에서 메모를 한 줄씩 입력한다. 입력 초안과 날짜 해석 기준일은 자동 보관된다.
3. **저장하고 로컬 정리**를 누른다. 저장 시 원문과 기준일을 고정한다. 같은 원문·기준일로 다시 누르면 기존 수집 항목을 연다.
4. 검토표에서 종류·내용·날짜·시각·분류를 수정한다. 애매한 항목은 선택 해제된 상태로 제안된다. **원문 보기**로 전체 원문을 확인할 수 있다.
5. **선택 항목 반영**을 누른다. 날짜가 있는 할 일·일정은 캘린더에 등록하고, 날짜 없는 할 일·아이디어·정보·확인 필요는 수집함에 누적한다.
6. **모아보기·요약**에서 날짜순·카테고리순 정렬과 분류 필터, 완료 처리를 사용한다. 항목을 두 번 누르면 해당 수집 기록의 검토창으로 돌아간다.
7. **전체 요약을 메모로 저장**하면 모든 분류의 미완료 항목을 일반 메모로 저장한다. 저장된 문서는 당시의 스냅샷이며, 동적 화면은 계속 갱신된다.

캘린더에 등록된 항목은 캘린더에서 수정한다. 수집함은 연결된 일정의 현재 내용·날짜·완료 상태를 읽는다. 캘린더에서 삭제한 항목을 다시 만들지 않는다.

## 외부 AI 설정

**프로그램 설정 → 외부 AI**에서 차단/허용을 선택하고 저장한다. 기본값은 차단이다. 취소하면 변경하지 않는다.

- 차단: 로컬 정리·저장·날짜 계산·알림을 사용한다. 외부 AI 요청은 불가능하다.
- 허용: 사용자의 향후 연결 의사를 저장한다. **현재 버전에는 연결 기능이 없으므로 허용해도 전송하지 않는다.** AI 정리 버튼은 비활성으로 표시된다.
- 실제 API 연결, 연결 확인, 자동 재시도, API 키 보관은 아직 없다.
- 이 설정은 외부 AI에 대한 설정이다. 캘린더 동기화 등 다른 서비스 전체의 네트워크를 제어하는 방화벽 설정이 아니다.

추후 외부 분석 어댑터를 추가할 때는 전송 직전 현재 허용 여부를 다시 읽고, 사용자가 명시적으로 요청한 메모만 전송해야 한다. 대기 작업·재시도에도 같은 검사와 차단 전환 시 취소가 필요하다. 이미 전송된 내용은 회수할 수 없다. 백업에서 허용 설정을 가져오는 경우의 재확인도 실제 연결 도입 시 다룬다.

## 날짜와 분류 규칙

- 한 번에 20,000자·200줄까지 처리한다. 한 줄에 섞인 복잡한 행동은 자동 분해하지 않고 확인 대상으로 남긴다.
- 오늘·내일·모레, 이번 주/다음 주 요일, 금요일, YYYY-MM-DD, M/D, M월 D일을 지원한다. 날짜가 문장 뒤에 있어도 읽는다.
- 날짜 해석은 저장 당시의 기준일을 사용한다. D-day는 화면을 볼 때의 현재 날짜로 계산한다. 화면을 다시 열 때와 표시 중 30초마다 갱신한다.
- 연도 없는 M/D는 기준 연도로 해석하며, 이미 지난 날짜라면 연도를 확인한다. 불가능한 날짜, 월말·조건문·반복·복수 날짜는 자동 등록하지 않는다.
- 오전/오후 시각과 HH:MM을 지원한다. `3시`처럼 오전·오후가 불명확하면 확인한다. `15:00`은 24시간제로 처리한다.
- 날짜만 있는 할 일은 해당 날짜의 종일 마감이다. 기존 캘린더 저장 관례에 맞춰 00:00–23:59로 기록한다. 작업 시간을 추정한 것이 아니다.
- 시각만 있는 할 일의 마감 표시는 기존 캘린더가 양수 길이를 요구하므로 해당 시각부터 1분 구간으로 저장한다. 추정 소요 시간이 아니다.
- 약속·회의 등 일정은 사용자가 날짜와 시작·종료 시각을 확정해야 등록한다. 종료 시각을 만들어 넣지 않는다. 밤을 넘기는 일정은 현재 검토창에서 나누어 등록한다.
- **시각 알림**은 기본 꺼짐이다. 날짜·시각이 있는 일정/할 일에 사용자가 체크하면 해당 시각의 기존 PC 알림을 생성한다. PC/앱 실행 등 기존 알림 동작 조건을 따른다.
- 분류는 `#업무` 같은 명시적 태그 또는 사용자가 검토창에서 지정한 이름을 사용한다. 미분류를 억지로 개인/업무로 판단하지 않는다.
- 검토창은 기존 메모 카테고리 이름을 선택지에 포함한다. 일정의 기본 분류(업무/개인/중요/학습/기타)에 없는 이름은 캘린더에서 기타로 표시하고, 원래 분류는 일정 상세와 수집함에 보존한다. 두 카테고리 저장 체계의 전면 통합은 하지 않았다.
- D-day는 기존 `목표일을 1일째로 세기` 설정을 따른다. 강조는 실제 날짜 차이 3일 이내의 미완료 일정·마감과 지연 항목에 적용한다.
- 아이디어는 날짜를 언급해도 자동으로 할 일로 승격하지 않는다. 사용자가 종류를 바꾸고 반영할 때만 전환한다.

## 보존·백업·중복 방지

수집 원문과 검토 데이터는 기존 메모 DB의 settings 테이블에 `memo_organizer_state_v1`로 저장한다. 새 스키마/별도 DB를 만들지 않는다. 입력 초안은 `memo_organizer_input_draft_v1` 및 기준일 키로 보관한다.

일정 반영과 수집 상태 기록은 하나의 SQLite 트랜잭션이다. 실패하면 모두 롤백한다. 수집 항목별 고정 ID와 등록된 일정 ID로 재반영 중복을 막는다. 등록 후 상태는 기존 일정 레코드가 기준이며 복사본을 따로 수정하지 않는다.

**앱 전체 백업/복원과 DB 백업에는 수집함이 포함된다. 메모 전용 `.tomamemo` 내보내기는 수집함을 포함하지 않는다.** 수집함을 옮기려면 전체 백업을 사용한다. 읽을 수 없는 수집함 데이터는 빈 값으로 덮어쓰지 않고 오류를 표시한다.

## 변경 범위

- 새 파일: `memo_organizer.py`(분석·검증), `memo_organizer_store.py`(수집·반영), `memo_organizer_panel.py`(화면), `external_ai_policy.py`(연결 정책).
- 기존 연결: 메모 화면에 탭 추가, 프로그램 설정에 외부 AI 탭 추가, 일정 저장 메서드에 호출자 트랜잭션 참여 옵션 추가.
- `main_window.py`, 파일 이름 변경 기능, 사용자의 운영 DB는 직접 수정하지 않는다.
- 모바일 화면, 외부 AI 실제 연결, 수동 AI 결과 가져오기, `.ics` 내보내기는 이번 구현에 포함하지 않는다.

- 배포는 검증된 변경 파일만 바탕화면 소스에 복사하고 해시로 동일성을 확인한다. EXE 재빌드와 실제 Windows 알림 팝업 수신 확인은 수행하지 않았다.
