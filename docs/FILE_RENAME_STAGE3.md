# 파일 이름 변경 3단계 — 2026-09-19

후속 4단계 채우기 핸들은 `FILE_RENAME_STAGE4.md`에 구현·검증 기록이 있다. 이 문서의 파일 실행/복구 계약은 그대로 유지한다.

소스로 프로그램을 다시 실행한 뒤 트레이의 `파일 이름 일괄 변경`을 연다. 기존 EXE는 새로 만들지 않았다. 이 단계부터 확인 창에서 승인하면 실제 이름이 바뀐다.

## 사용법

1. 탐색기 선택 단축키 또는 드롭으로 파일을 가져와 입력 열을 편집한다.
2. 금지 문자·예약 이름·중복·기존 파일/폴더 충돌·경로 길이 문제는 붉은 배경과 툴팁으로 표시한다. 이름 앞 공백은 유지하며 경고한다. 모든 입력이 빈 행과 현재 이름과 같은 행은 실행하지 않는다.
3. 기본적으로 문제 행이 하나라도 있으면 실행을 막는다. `문제 행 제외`를 직접 선택하면 독립적으로 실행 가능한 행만 대상이 된다. 이동할 수 없는 파일의 이름을 다른 행이 사용하려는 경우도 함께 제외한다.
4. `문제 행만`으로 범위를 좁히고 `사유 복사`로 검사/실행 실패 사유를 복사할 수 있다. 필터에서 숨긴 행에 붙여넣거나 행 순서를 바꾸는 것은 막는다.
5. `이름 바꾸기`를 누르면 파일을 다시 확인하고 최종 확인 창을 연다. 상세 내용의 원본→목표 경로와 개수를 확인한다. 기본 선택은 취소(No)다.
6. 성공한 행은 현재 이름을 갱신하고 입력을 비운다. 실패·복구 필요·미실행은 개수와 행 툴팁으로 남는다. 실제 실행 후 표 편집 Undo 이력은 비운다.
7. 실제 이름을 되돌릴 때는 `파일 변경 취소`를 누른다. 표의 Ctrl+Z와 다르다. 최근 10개의 완료된 실행 중 마지막 미취소 실행이 대상이며, 확인 후 내용/식별자·충돌을 다시 검사한다. 외부에서 편집한 파일이나 원래 이름에 생긴 다른 파일을 덮어쓰지 않는다.

## 실패·종료 후 복구

- 이름 맞바꾸기와 연결된 이름 변경은 의존 그룹 하나로 처리한다. 원본→고유 임시 이름→목표 이름 순서이며, 오류가 나면 해당 그룹의 원상복구를 시도한다. 복구된 실패와 독립적인 그룹은 계속 실행할 수 있다. 복구 불가 상태가 남으면 새 그룹 실행을 중단한다.
- 다시 실행한 앱에서 이름 변경 창을 열면 미완료 기록을 확인하고 새 실행/파일 취소를 막는다. 자동으로 파일을 옮기지 않는다.
- `미완료 복구` 상세 창에서 원본·임시·목표 경로를 보고 승인한다. 이미 완료된 그룹은 유지하고 중단된 그룹만 실행 전 이름으로 되돌린다. 복구 확인 후 표 목록/입력은 비우므로 다시 불러온다.
- 복구 경로의 충돌, 외부 편집, 파일 누락, 폴더 변경, 잠금이 있으면 자동 복구를 중단하고 기록을 남긴다. 충돌 파일을 자동 삭제하지 않는다. 내용을 확인하고 잠금 등 원인을 해소한 뒤 다시 복구한다. 임시 파일이나 일지를 임의 삭제하지 않는다.
- 실행 취소 도중 종료되어도 같은 복구 흐름을 쓴다. 중단된 취소는 취소 직전 상태로 복구하고 다시 `파일 변경 취소`할 수 있다.

## 기록과 안전 경계

- 일지는 `%LOCALAPPDATA%\CodexShortcutLauncher\rename_history\history.sqlite3`에 별도 저장한다. `storage_config.user_storage_root()`를 사용하며 사용자 데이터 폴더 변경과 메모·설정 백업 복원에서 분리된다. 기존 `store.py`/사용자 DB 스키마는 바꾸지 않았다.
- SQLite FULL 동기화로 전체 계획과 각 이동의 의도를 먼저 기록한다. 완료 이력도 자동 삭제하지 않으며 미완료 기록은 반드시 보존한다. 화면에서 취소 대상으로 선택하는 범위만 최근 완료 실행 10건이다. 기록 폴더를 삭제하면 자동 복구/취소에 필요한 정보가 사라진다.
- 동일 일지의 실행/복구/취소는 Windows 파일 잠금으로 직렬화한다. 일지 생성/읽기 실패나 알 수 없는 기록 버전에서는 실행을 막는다.
- 사용자 파일을 삭제·덮어쓰기·내용 변경하는 호출은 사용하지 않는다. 실제 이동은 쓰기/삭제 공유를 막은 원본 핸들에서 파일 ID·크기·수정 시각·SHA-256을 확인한 뒤 수행한다. 목표가 뒤늦게 생겨도 덮어쓰지 않고 실패하도록 설정한다. 근거: Microsoft [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info), [CreateFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea).
- 지원 범위는 Windows 로컬 일반 파일의 같은 폴더 내 이름 변경이다. 확장자는 유지한다. 네트워크/확장 경로, 심볼릭 링크·재분석 경로, 하드 링크, 식별자 없는 파일, 260 UTF-16 코드 단위 이상의 경로는 거부한다. 임시 이름을 만들 공간도 검사한다.
- 내용 확인 중에는 화면이 응답을 기다릴 수 있다. 대용량 파일/대규모 목록 성능은 별도 확인이 필요하다. 프로세스 강제 종료 복구를 검증했으나 저장 장치 고장·전원 차단까지 무손실을 보증하지 않는다.
- 표 작업 영역은 최소 210px를 확보한다. 실행 모드 최소 창은 620×470이며, 앱 글꼴/테마가 커지면 Qt가 창을 더 키울 수 있다.
- 원본 파일/사용자 메모·설정은 개발 검증에 사용하지 않았다. 테스트에서 생성한 임시 파일과 임시 일지만 변경했다.
