# 계획 검토 반영 — 2026-09-19

이 문서는 2단계 착수 당시 검토 기록이다. 이후 승인된 3단계의 구현·일지 분리·취소 범위·검증은 `FILE_RENAME_STAGE3.md`와 메인 계획 상단을 따른다. 아래 OCR·모바일·제목 필터의 후속 경계는 유지한다.

## 적용 순서

현재 상태는 `1._PROJECT_PLAN.md` 상단 표, 확정 계약은 `DECISIONS.md`와 최신 날짜의 확정 결정, 실제 미확인은 `3._TODO.md`를 기준으로 한다. 옛 단계의 승인 대기/완료 수치는 당시 기록이다. 근거 없는 기간은 반복하지 않는다. 기존 메모·백업·사용자 데이터 계약은 변경하지 않는다.

## 이번 반영과 후속 경계

- 이번 코드는 파일 이름 변경 2단계와 현재 이름 채우기·목록 행 제거·변경 미리보기다. 파일 실행, DB 변경, OCR, 모바일, 제목 필터 구현은 포함하지 않는다.
- 이름 변경 3단계는 의존 그룹·사전 일지·재시작 복구·덮어쓰기 금지부터 구현한다. swap, chain, 대소문자 변경, 잠긴 파일, 외부 충돌, 각 이동 지점 강제 종료, 복구 중 실패를 임시 파일로 검증한다. 손실 없이 복구했음을 입증하지 못하면 실행을 활성화하지 않는다.
- 모바일은 기존 전체 백업과 읽기 전용 전송 범위를 분리한다. 휴지통/과거 버전/알림 등 제외 항목이 실제 전송되지 않는지 manifest뿐 아니라 payload를 검사한다. 전송 전 개수·크기·제외 사유, 최신본 교체 실패 시 직전 성공본 유지, 링크 v1/v2 및 접기 메타 표시를 검증한다. 읽은 위치·글자 크기는 휴대폰 로컬 설정으로만 저장한다.
- OCR 결과는 메모에 넣기 전에 편집 가능하게 보여주고 줄바꿈 정리와 인식 원문 복원을 제공한다. 사용자 확인 전 기존 메모를 바꾸지 않는다.
- 제목 필터 G-C/G-D는 공유 레이아웃·좁은 폭 검사를 함께 설계하되 단계별 승인 게이트를 유지한다. G-F 자동완성은 한글 IME 조합 중 Enter와 제안 선택 Enter를 구분하고, 선택 한 번을 Undo 한 번으로 취소하며 원래 제목/기호를 보존한다.

## 충돌 정리

- 제목 분류의 빈 상태는 `기호`/`머리말` 텍스트다. `☆`/`[ ]`는 폐기된 시안이다. 해당 문서의 결정표·자동검사·수동검사를 일치시켰다.
- 메모 Phase 4~7 완료 후에도 남은 승인 대기 문구는 이력으로 구분했다. 8번 계획 Q1/Q2, 9번 Q4/Q5는 이미 A로 확정되어 재질문하지 않는다.
- D-Day는 공통 deadline 규칙(7일 이내 주황, 오늘/지난 기한 빨강)을 기준으로 한다. 예전 3일/빨강 시안을 새 구현 기준으로 쓰지 않는다.
- 값 입력 휠은 최신 오조작 방지 정책을 따른다. 10번 문서의 휠 허용 시안은 폐기한다. 실제 컨트롤별 설치 여부와 직접 입력·화살표 동작은 별도 확인하며, 문서 불일치를 실제 버그로 단정하지 않는다.

## 검증 보고 계약

매 변경에서 기준 커밋과 변경 파일, 명령, 실행 환경, 통과/실패/건너뜀, 프로세스 종료 코드를 기록한다. 네이티브 충돌/시간 초과 후 분할 통과는 최초 실패도 함께 기록한다. 테스트 개수만으로 실창 확인을 대체하지 않는다. 실제 탐색기·엑셀·IME·포인터·배율 확인은 자동검사와 분리한다.
