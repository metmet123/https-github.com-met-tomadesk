## 2026-08-07 메모·캘린더 UI 시안 중심 개편

### 요청과 목표

- 확정된 계획에 따라 고정 상세 패널을 필요할 때만 여는 편집 서랍으로 변경한다.
- 캘린더 면적·일정 정보 위계·월간 밀도·반응형 동작을 개선하면서 기존 기능과 데이터를 보존한다.

### 처리

- 1180px 이상은 `220px 탐색 + 캘린더 + 380px 편집 서랍`, 900~1179px는 캘린더 위 겹침 서랍, 900px 미만은 전체 폭 편집기로 구성했다.
- 편집 서랍을 기본 닫힘으로 바꾸고 상단 저장·닫기, 미저장 확인, 저장 후 닫기, `추가 설정` 접기, 반복 발생 전용 항목을 구현했다.
- 빠른 메모를 편집 탭에서 분리해 헤더 버튼과 기존 전역 단축키로 열도록 유지했다.
- 일간·주간 일정에 시간·제목·카테고리·상태 위계를 적용하고 월간 보기를 최대 3개 일정 칩과 `+N개 더보기`가 있는 사용자 정의 6주 그리드로 교체했다.
- 일정 이동 취소를 5초 상태 메시지로 바꾸고 정상 한글 일정으로 실제 화면 검증 이미지를 생성했다.
- 캘린더 보기 코드를 `calendar_timeline_view.py`, `calendar_month_view.py`로 분리했으며 기존 신호·DB 스키마·일정 데이터 형식은 유지했다.

### 검증과 배포

- 일정·알림 및 신규 서랍 테스트 26건을 한 묶음으로 통과했다.
- 기존 기능 57건과 반응형 UI 8건은 각 테스트를 독립 프로세스로 실행해 65/65건 통과했다.
- 한 프로세스에서 `MainWindow`를 반복 생성·종료하는 기존 Qt 묶음 방식은 Windows 네이티브 종료 코드 `0xC0000409`가 있어 독립 프로세스 결과와 실제 실행으로 교차 검증했다.
- `output/calendar_ui/`의 1440×900, 1100×800, 800×900 화면에서 한글·잘림·서랍 전환·월간 칩·여백을 확인했다.
- 임시 DB로 실제 Windows `MainWindow`를 5초 실행한 뒤 정상 종료 코드 0과 임시 DB 생성을 확인했다.
- 실제 사용자 키보드·마우스 조작감 확인은 기존 TODO로 유지한다. 사용자 DB·백업은 변경하지 않았고 EXE는 생성하지 않았다.
