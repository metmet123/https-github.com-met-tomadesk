# 설계 결정

## 2026-08-31 3-수식키 지원과 알림 미러 일정 보호

- 결정: 새 메모 기본 단축키 `Ctrl+Alt+Shift+N`을 유지하고 파서·입력 빌더·Windows 등록 경로가 수식키 3개를 동일하게 지원한다.
- 결정: 잘못되거나 중복된 단축키 변경은 기존 단축키 값을 유지하고, 시작 방식·저장 위치·토마펫 같은 다른 설정은 저장할 수 있게 한다.
- 결정: `source_reminder_id`가 있는 일정은 읽기 전용으로 표시하고 메모 알림 설정에서만 변경한다.
- 결정: 알림 변경 시 미러 일정을 삭제·재생성하지 않고 같은 일정 ID의 제목·내용·연결 메모·시간만 갱신해 분류·우선순위·미리 알림을 보존한다.
- 이유: 기존 기본값과 사용자 데이터 형식을 유지하면서 설정 차단과 미러 일정의 무음 데이터 소실을 함께 방지하기 위해서다.

## 2026-08-07 메모 다중·반복 알림과 처리 이력

- 결정: 메모 한 개에 여러 활성 알림을 허용하고 포스트잇 메모에도 같은 규칙을 적용한다.
- 결정: 반복 시리즈는 단발·매일·평일·매주·매월과 종료일·횟수 제한을 저장하며, 현재 발생 수정과 전체 반복 수정을 구분한다.
- 결정: 완료·미루기·건너뛰기를 별도 처리 이력으로 보존하고 예정 알림은 알림 ID별로 캘린더에 투영한다.
- 결정: 기존 DB는 같은 폴더에 SQLite 백업을 성공적으로 생성한 뒤에만 `UNIQUE(note_id)`를 제거하는 마이그레이션을 실행한다.
- 결정: 알림 본문은 저장 시점의 메모 일반 텍스트 스냅샷이며 이후 메모 수정으로 자동 변경하지 않는다.
- 결정: 원본 `15_알림노트`의 UI는 복사하지 않고 기능 모듈의 프로젝트 복사본만 현재 UI에 맞게 수정한다.
- 이유: 현재 UI와 기존 사용자 데이터를 보존하면서 원본 알림노트의 편집·반복·이력 기능을 충돌 없이 통합하기 위해서다.
- 변경 관계: 2026-08-04의 `메모 한 개당 활성 알림 한 개`와 반복 일정 제외 결정, 2026-08-05의 단일 알림 캘린더 결정은 이 결정으로 대체한다.

## 2026-08-07 캘린더 중심 편집 서랍 구조

- 결정: 일정 편집기는 기본 닫힘으로 두고 새 일정 또는 일정 선택 시에만 연다.
- 결정: 1180px 이상에서는 캘린더 옆 고정 폭 서랍, 900~1179px에서는 캘린더 위 겹침 서랍, 900px 미만에서는 캘린더를 잠시 대체하는 전체 폭 편집기로 표시한다.
- 결정: 빠른 메모는 일정 편집기와 분리하고 월간 보기는 일정 칩을 직접 표시하는 사용자 정의 그리드를 사용한다.
- 이유: 기존 데이터와 외부 호출 계약을 유지하면서 일정 확인 면적과 편집 집중도를 동시에 확보하기 위해서다.

## 2026-08-06 메모·일정관리 데이터와 단축키 구조

- 결정: 기존 `reminders`를 삭제하거나 치환하지 않고 새 일정 테이블에 원본 ID로 연결해 호환 투영한다.
- 결정: 기존 메모 DB에 일정 스키마를 처음 추가할 때 같은 폴더에 업그레이드 전 SQLite 백업을 자동 생성한다.
- 결정: 일정은 일간·주간·월간·목록의 하이브리드 화면으로 제공하고 좁은 창에서는 상세 편집기를 아래쪽 스크롤 영역으로 재배치한다.
- 결정: 빠른 메모·오늘 일정·통합 검색과 메모·일정별 단축키를 모두 변경 가능하게 하고, 기존 작업·제어 단축키와 통합 충돌 검사를 수행한다.
- 이유: 기존 사용자 데이터와 조작 습관을 보존하면서 일정관리 기능을 확장하고, Windows 전역 단축키 중복으로 인한 실행 오류를 예방하기 위해서다.

## 2026-08-05 알림 입력과 캘린더

- 결정: 알림 메모 내부를 메모 편집과 캘린더 탭으로 분리하고 같은 날짜·시간 입력 컴포넌트를 공유한다.
- 결정: 캘린더는 기존 메모별 단일 알림 테이블을 기간 조회하며 별도 일정 테이블과 반복 일정은 추가하지 않는다.
- 결정: 빈 시간에서 만드는 빠른 알림은 독립 알림이 아니라 새 메모와 연결된 알림으로 저장한다.
- 결정: 숫자 날짜·시간 해석만 GUI에서 분리해 공통 라이브러리에 반영한다.
- 이유: 기존 데이터 호환성과 알림 생명주기를 유지하면서 원본 알림노트의 일정 사용성을 가져오기 위해서다.

## 2026-08-04 알림 메모 통합

- 결정: 기존 화면은 보존하고 최상위 화면 전환으로 `알림 메모` 패널을 추가한다.
- 결정: 알림 메모는 같은 데이터 폴더의 `alert_notes.db`에 분리 저장하고 전체 JSON 백업에서 두 DB를 함께 다룬다.
- 결정: 메모 한 개당 활성 알림은 한 개로 제한하며 포스트잇 상태에서도 알림을 허용한다.
- 결정: 알림노트 원본의 트레이·캐릭터·반복 일정·전역 단축키는 통합하지 않는다.
- 이유: 기존 단축키 DB의 `history` 테이블 충돌과 런타임 제어 중복을 피하면서 핵심 기능만 재사용하기 위해서다.

## 2026-08-04 반복작업 재생 설정

- 결정: 신규 매크로는 `timing_mode: scaled`, `playback_speed`, `repeat_count`를 저장한다.
- 결정: 반복 횟수 범위는 1~999회이며 값이 없는 기존 매크로는 1회로 실행한다.
- 결정: 기존 `recorded` 데이터는 1.0배로 편집·실행하고, `fixed` 데이터는 편집 전 직접 실행 호환을 유지한다.
- 결정: 반복 사이의 별도 대기 설정은 추가하지 않고 매크로 마지막 대기 단계로 조절한다.
- 이유: 화면 설정을 단순화하면서 기존 데이터와 중지 단축키의 실행 계약을 보존하기 위해서다.

## 2026-08-03 제외 앱 단축키 처리 방식

- 결정: 제외 앱에서는 콜백만 중단하지 않고 해당 작업의 `RegisterHotKey` 등록을 해제한다.
