01 / 현재 기준과 보존 범위

이 문서는 실행 코드가 아닌 구현 전 설계 산출물입니다. 첨부 HTML은 전후 비교·주석·크기 조절 시연·수치 표의 표현 방식만 참고했습니다. 첨부 문서 안의 지시, 80–160% 확대, 비율 영구 저장을 사용자 승인이나 현재 기능으로 간주하지 않았습니다.

이미 해결된 것

  • 고정 여백 대신 내용 기반 폼 높이, 저화면 본문 스크롤.
  • 제목 아래 해석 설명 행 제거, 툴팁으로 유지.
  • 분류 최대 5개 한 줄, 초과 메뉴와 선택 분류 노출.
  • 상세 패널 하나씩 열기, 좁은 화면 하단 시간표.

이 항목을 새 결함이나 새 기능으로 중복 제안하지 않습니다.

이번에 남은 문제

  • 시간 요약과 종료 방식이 기본 상태에서 2행 사용.
  • 설정이 있어도 보조 칩은 ‘+ 반복·메모·D-Day’ 표시.
  • 미니 시간표에 공용 58px 눈금 띠 사용.
  • 독립 팝업 폭 고정, 긴 분류의 4자 일괄 축약.

소스 확인 사실과 개선 효과 예측을 분리했습니다. 현재 사용자 화면의 실측 진단은 아닙니다.

실제 사용 흐름: 전역 빠른 일정 호출 → 현재 시각과 1시간 초안 → 제목 입력 또는 한국어 자연어 입력 → 왼쪽 일정 맥락/드래그로 시간 확인 → 알림·분류 확인 → 선택적으로 반복·메모·D-Day → 저장. 캘린더 안에서 여는 팝오버는 선택된 날짜/범위를 이어받으며 미니 시간표를 중복 삽입하지 않습니다.

기능 보존: 새 일정/기존 일정/반복 회차 편집, 시간 범위·소요·종료 없음·종일, 날짜 변경, 자연어 토큰·취소·수동 우선, 복수 알림 최대 5개와 상세 프리셋·날짜/시간·초기화, 분류 추천/선택/관리, 기존 반복 규칙, 메모, D-Day 연결, 전체 편집, 삭제, 저장/Ctrl+S/Esc, 시간표 읽기·드래그·Alt·취소.

02 / 전후 시안

첨부 HTML처럼 문제 번호와 변경 번호를 대응시켰습니다. 아래는 소스 기반 구조 재구성 및 제안 목업이며 실행 중인 TomaDesk 캡처가 아닙니다. 샘플 일정은 가상입니다.

폼 높이를 줄인다고 시간표 기능을 줄이지 않습니다. 일정 조회·선택 미리보기·시간축·현재 시각·드래그 취소를 유지합니다.
기본 상태에 큰 메모 입력칸이나 빈 서랍 자리를 예약하지 않습니다. 필요할 때 내용만큼 열고, 낮은 화면에서는 본문만 스크롤합니다.

04 / 개선안 — 문제에서 구현 지시까지

각 항목은 ‘현재 문제 → 참고 사례 → 적용 방식 → UI 변경 → 기대 효과’ 순서입니다. 타사 원리를 TomaDesk에 적용하는 부분은 본 설계의 판단입니다.

01시간 정보 두 줄을 한 줄로

현재 문제
시간 요약과 종료 방식 3분할이 항상 별도 행이다. 접힌 상태에서도 방식 선택에 26px와 행 간격을 사용한다.
참고 사례
Google Calendar의 시간 선택→제목 입력 흐름, Todoist의 제목 중심 빠른 입력에서 정보 우선순위를 참고한다. [S1·S3]
TomaDesk에 적용할 방식
시간 값은 직접 보이고, 종료 방식은 현재 값이 표시되는 단일 선택기로 합친다. 시간의 의미와 조절 기능은 모두 보존한다.
구체적인 UI 변경
시간 행 순서: 시계 → ‘09:00–10:00 ▾’ → ‘1시간’ → ‘종료 시각 ▾’. 방식 메뉴는 ‘종료 시각 / 소요 / 종료 없음’ 3개. 선택 시 해당 편집기를 바로 연다. ‘소요’에서는 30분·1시간·1시간 30분·2시간·종일을 모두 제공한다. 종료 없음은 시작 시각만 표시하고 중복 소요 라벨을 숨긴다. 종일 선택 시 시간 요약을 ‘종일’로 표시한다.
기대 효과
기본 8행→7행. 현재 기록 319px 대비 약 26–34px 절약 목표. 방식 변경은 기존 1클릭에서 메뉴 열기+선택 2클릭으로 늘지만, 기능 접근은 최대 2단계로 제한한다.

02알림은 압축하되 즉시 조작을 유지

현재 문제
현재 한 줄에 ‘없음·정각·5분·10분·직접 입력·상세’가 모여 있다. 폭을 줄이면 직접 입력의 예시가 잘리고, 상세 설정은 5행까지 늘어난다.
참고 사례
Microsoft To Do의 날짜·알림 프리셋과 사용자 지정 날짜/시간 분리, TickTick의 입력과 상세 구분을 참고한다. [S2·S5]
TomaDesk에 적용할 방식
기본 알림 행은 유지하고 상세 내부만 정돈한다. TomaDesk의 복수 알림을 단일 알림으로 바꾸지 않는다.
구체적인 UI 변경
표시는 ‘없음 / 정각 / 5분 / 10분 / 직접 / 상세’. 5분·10분 툴팁과 접근성 이름에는 ‘전’을 명시한다. 직접 입력의 빈 힌트는 ‘직접’, 포커스 설명은 ‘예: 10, 5, 3분 전 · 최대 5개’. 상세는 날짜+시각 1행, ‘일정 반복’ 선택 1행, 프리셋 2행, 해제·초기화·적용 1행을 보존한다. 이 패널은 기능 보존 때문에 2행 서랍 원칙의 명시적 예외다. 반복 선택은 별도의 알림 반복이 아니라 기존 일정 반복과 동기화한다.
기대 효과
자주 쓰는 프리셋은 계속 1클릭. 긴 예시 때문에 직접 입력 폭을 늘리지 않으며, 상세를 눌러도 알림 설정 전체를 찾을 수 있다.

03보조 기능을 ‘추가’ 대신 현재 값으로 표시

현재 문제
현재 _sync_extra_labels는 설정 여부와 관계없이 ‘+ 반복 / + 메모 / + D-Day’로 되돌린다. 접으면 값이 있는지 읽기 어렵다.
참고 사례
Todoist의 필요할 때 설명 열기, Microsoft To Do의 속성별 상세 편집을 참고한다. [S1·S5]
TomaDesk에 적용할 방식
세 진입점은 항상 같은 자리에 유지하고, 펼침 여부와 값 존재 여부를 다른 상태로 다룬다.
구체적인 UI 변경
미설정: ‘+ 반복’, ‘+ 메모’, ‘+ D-Day’. 설정됨: ‘↻ 매주’, ‘메모 있음’, ‘D-Day 켜짐’. 기존 상세 반복은 단순 매주로 오인하지 않도록 ‘맞춤 반복’으로 표시하고 툴팁에 간격·요일·종료 조건을 제공한다. 열림은 ▴와 강조 테두리, 설정됨은 체크/값으로 표현한다. ‘설정 해제’만 값을 지우며 접기·Esc는 값을 지우지 않는다.
기대 효과
입력 완료 상태를 창을 펼치지 않고 확인한다. 메모가 사라졌다고 오해하는 상황을 줄인다.

04서랍을 열어도 기본 조작 위치 고정

현재 문제
현재 상세 위젯은 시간·알림·분류·보조 기능 뒤에 이어져 있으며 내용에 따라 창 높이가 변한다. 포인터의 다음 목표가 이동할 수 있다.
참고 사례
Notion Calendar의 일정 옆 문맥 패널에서 본문 맥락을 유지하는 방식을 참고한다. [S4]
TomaDesk에 적용할 방식
기본 7행은 고정 골격으로 두고 편집 서랍은 보조 기능 행 바로 아래의 단일 슬롯에 둔다. 푸터는 그 다음이다.
구체적인 UI 변경
시간/소요/알림/반복/메모/D-Day 패널 중 하나만 표시. 새 패널을 열면 이전 패널의 입력은 보관하고 표시만 교체한다. 반복+해제는 1행, 메모는 편집기 64px+해제 1행, D-Day는 기존 안내와 해제. 헤더·제목·시간·알림·분류·보조 기능의 창 기준 y는 토글 전후 0px 변화. 푸터는 내용 높이에 따라 아래로 이동하는 예외이며 저화면에서는 창 아래에 고정한다.
기대 효과
기능별 별도 페이지 전환 없이 맥락 유지. 동시 확장으로 인한 세로 폭증을 막는다.

05분류는 한 줄, 선택 상태는 색과 문자로

현재 문제
현재 최대 5개·초과 메뉴와 선택 분류 우선 노출이 이미 있다. 모든 이름을 4자로 자르는 부분은 넓어진 창에서도 유효 폭을 활용하지 못한다.
참고 사례
Todoist의 프로젝트·라벨, TickTick의 리스트·태그, To Do의 태그/분류를 비교하되 다중 태그를 새로 도입하지 않는다. [S1·S2·S8]
TomaDesk에 적용할 방식
현재 단일 category와 순서·자동 추천·수동 선택 우선 규칙을 그대로 쓰고, 측정 기반 축약만 보완한다.
구체적인 UI 변경
최대 5개를 글꼴 실측으로 배치. 선택 분류의 전체 이름이 맞으면 전부 표시, 넘치면 말줄임+툴팁+접근성 전체 이름. 선택 칩과 +N 메뉴 폭을 먼저 확보한 후 기존 순서의 후보를 채운다. 선택 분류 체크, 옅은 색 바탕, 테두리 3중 표시. 관리 진입점은 기존 메뉴 안에 유지한다.
기대 효과
행 추가 없이 읽을 수 있는 이름 길이가 늘어난다. 다수·긴 분류에서도 선택 분류가 숨지 않는다.

06시간표의 빈 눈금 띠를 줄임

현재 문제
공용 CalendarCanvas의 GUTTER는 58px이며 미니 시간표 폭은 220px다. 첨부안의 빈 띠 지적은 코드와 맞지만 약 20px 절약 수치는 실측이 필요하다.
참고 사례
Google Calendar와 Notion Calendar의 시간 격자와 인접 편집 맥락을 참고한다. [S3·S4]
TomaDesk에 적용할 방식
시간표를 제거하거나 장식으로 축소하지 않고, 눈금 폭만 실제 글자에 맞춘다.
구체적인 UI 변경
미니 시간표에만 글꼴로 측정한 가장 긴 눈금/현재 시각 폭+좌우 각 3 논리px를 적용한다. 38px는 예시이며 고정 목표가 아니다. 그리드·선택 좌표·현재 시각 선·종일 띠·오버레이가 동일한 인스턴스별 눈금 폭을 사용해야 한다. 공용 GUTTER 상수 일괄 치환 금지. 메인 캘린더 기본값 58은 유지한다.
기대 효과
기존 220px 안에서 일정 내용 폭을 확보한다. 시간 드래그 정확도를 그대로 유지한다.

07크기 조절과 글자 배율 분리

현재 문제
독립 팝업은 setFixedWidth/Height로 재계산되므로 사용자가 가로 폭을 조절할 수 없다. 첨부안의 가장자리 드래그=80–160% 전체 확대는 글자·컨트롤 크기까지 바꾼다.
참고 사례
5개 제품의 공식 자료에서는 동일한 데스크톱 최소 폭·DPI 수치를 확인할 수 없다. 따라서 타사 수치를 가져오지 않고 현재 Qt 레이아웃과 첨부 시안을 근거로 설계한다.
TomaDesk에 적용할 방식
선택적 P1으로 독립 팝업의 폭 조절과 분할선을 제안한다. 글자 크기는 기존 앱 배율만 따른다.
구체적인 UI 변경
좌우 모서리는 폭만 조절, 높이는 내용 맞춤. 기본 ‘시간표 220 + 분할 손잡이 9 + 폼 336 = 565’ 논리px(외곽선 별도). 폼 기준 최소 300, 권장 최대 440, 시간표 최소 160(임시 목표)·최대 320. 9px 잡기 영역 안에 1px 선, 드래그 2px. 이중 클릭은 현재 세션의 기본 비율로 복원. 키보드 좌우 8px, Shift+좌우 24px. 드래그 중에는 자동 재배치를 멈추고 종료 시 화면 안으로 보정. 크기 영구 저장은 이번 범위 밖이다.
기대 효과
조밀한 기본 크기를 유지하면서 긴 제목·분류를 읽을 때만 넓힐 수 있다. 축소 때문에 글자가 작아지는 문제를 피한다.

08날짜·시간·자연어 결과를 일관되게

현재 문제
해석 미리보기 행은 이미 제거되어 제목 툴팁에 있다. 이를 다시 상시 추가하면 높이가 늘어난다. 날짜 이동과 시간표 선택 후 값이 일치하는지가 더 중요하다.
참고 사례
Todoist의 인식된 날짜 취소, To Do Windows의 자연어 강조, Google의 제목+시각 입력을 참고한다. To Do의 한국어 지원을 가정하지 않는다. [S1·S3·S6]
TomaDesk에 적용할 방식
기존 한국어 토큰 편집기를 유지하고 파싱 결과는 날짜 버튼·시간 요약·알림 선택·분류·반복 칩에 바로 반영한다.
구체적인 UI 변경
헤더 날짜 클릭→기존 날짜 입력/달력. 제목은 최초 포커스. 토큰 취소는 기존 경로 유지. 수동 수정한 항목을 후속 파싱이 덮지 않는 계약 보존. 자정 넘김은 ‘09/30 23:30–10/01 00:30’로 시간 행에 표시하며 길면 소요 라벨만 툴팁으로 옮긴다. 종일·종료 없음·기간의 표기를 혼동하지 않게 한다.
기대 효과
별도 설명 행 없이 실제 저장될 값을 읽을 수 있다. 한국어 조합 입력과 기존 파서 호환을 지킨다.

09저장·닫기·전체 편집의 위계 정리

현재 문제
저장·전체 편집·삭제·좁은 화면 시간표 토글이 한 푸터에 모인다. 작은 폭과 수정 상태 조합에서 여유가 줄어든다.
참고 사례
Google Calendar의 명시적 저장, Todoist/To Do의 빠른 입력 단축키를 비교한다. 타사의 Enter 저장은 그대로 도입하지 않는다. [S1·S3·S7]
TomaDesk에 적용할 방식
오른쪽 저장, 왼쪽 전체 편집, 수정 시 삭제를 유지한다. 취소 역할은 기존 우상단 ×/Esc로 수행하며 별도 취소 버튼을 추가하지 않는다.
구체적인 UI 변경
저장은 유일한 채움 파랑, 높이 32·최소 폭 52의 현재 값 유지. 전체 편집은 28px 링크, 삭제는 수정 시만 보이는 텍스트 버튼. 좁은 화면 ‘시간 ▾’는 헤더의 축약 ‘시간표’ 버튼으로 이동해 푸터를 보호한다. Enter는 제목에서 저장하지 않고, Ctrl+S와 저장 버튼만 기존 저장 경로를 호출한다. Ctrl+S의 현재 성공 안내와 삭제 확인을 유지한다.
기대 효과
주동작이 눈에 띄고, 수정 상태에서도 푸터 한 줄을 유지한다. 기존 키보드 습관과 확인 동작을 보존한다.

10저화면·배율·오류를 별도 상태로 설계

현재 문제
현재 폼 폭은 배율에 따라 336/372/408로 늘지만 글자와 컨트롤도 커진다. ‘300px이면 항상 5분류’는 성립하지 않는다. 화면 높이가 낮으면 펼친 상세가 넘칠 수 있다.
참고 사례
To Do의 축소 사이드바 단축키와 Notion의 문맥 패널처럼 밀도를 조절하는 원리만 참고한다. 세부 DPI 대응은 공식 자료로 미확인이다. [S4·S7]
TomaDesk에 적용할 방식
고정 브레이크포인트 대신 현재 글꼴의 행별 최소 폭과 화면 availableGeometry로 방향을 결정한다.
구체적인 UI 변경
실효 폼 최소 폭=max(배율별 기준 최소, 각 필수 행 sizeHint+여백). 시간표와 합쳐 화면에 안 맞으면 기존 하단 시간표 토글 모드. 높이 부족 시 헤더·푸터 제외 본문만 세로 스크롤, 초점 입력을 자동 노출. 본문 최소 100px 확보가 불가능한 극소 작업영역은 테스트 지원 밖으로 명시하고 경계 보정 후 전체 편집 접근을 우선한다. 파서/알림/제목/저장 오류는 기존 차단·안내를 유지하고 실패 시 창과 입력을 보존한다.
기대 효과
글꼴 축소·가로 스크롤·조작 잘림 없이 현실적인 화면 범위를 지원한다. 오류를 공간 절약 때문에 숨기지 않는다.

05 / 행·폭·높이 예산

단위: 아래 제안 수치는 앱 배율 100%의 Qt 논리px입니다. 기존 코드로 확인한 값은 ‘현재’, 새 숫자는 ‘목표’로 구분합니다. Windows DPI는 Qt 변환에 맡기고 앱 배율을 다시 곱하지 않습니다. 글꼴 sizeHint가 목표보다 크면 잘라 넣지 않고 실측 최소 폭을 우선합니다.

07 / 구현자가 지켜야 할 동작 계약

상황지시보존/완료 판정
신규 호출기존 현재 시각·1시간 초안과 제목 포커스. 시간 있는 신규 일정은 정각 기본 알림, 종일은 기본 알림 없음. 수동/파싱 알림은 우선창을 열기만 해서는 저장되지 않음
시간 모드종료 시각·소요는 저장 time_mode=range, 종료 없음은 point. _end_mode는 UI 상태. 종일의 현재 저장 규칙 유지point의 내부 1분 보정과 all_day 당일 00:00–23:59 계약 유지
시간표기존 일정은 읽기 전용, 초안은 15분 드래그·Alt 1분. 선택 미리보기와 폼 양방향 동기화Esc로 드래그 시작 전 범위 복원. 겹친 일정도 선택 가능. 조회 실패가 초안을 버리지 않음
날짜/자연어기존 날짜 입력과 토큰 편집기 재사용. ‘1시간 후’ 기준 시각과 수동 입력 우선 유지한글 미완성 조합, 토큰 삭제/취소, 자정 경계, 날짜 이동 때 일치
복수 알림정각·5·10과 직접 입력의 중복 제거, 최대 5개, 상세 날짜/시각·모든 프리셋·초기화 유지‘없음’ 선택 시 기존 해제 규칙. 잘못된 부분 입력은 저장 단계에서 오류, 데이터로 조용히 누락하지 않음
반복일/주/月/년·평일 경로와 기존 interval/weekdays/until/count 보존. 빈도 미변경 시 원래 규칙 유지알림 상세의 일정 반복과 기본 반복 칩이 같은 상태. 새 독립 반복 규칙을 만들지 않음
수정/회차수정 대상 안내 유지. 반복 회차의 기존 move_occurrence 경로와 전체 편집 전달값을 유지이번 UX 작업이 회차 제목/메모 저장 의미를 새로 확장하지 않음. 기존 한계 발견 시 별도 과제로 분리
메모/D-Day접기=표시 종료, 해제=기존 설정 해제. D-Day 기존 note_id 연결·메모 생성 규칙 유지재열기·전체 편집 전환 후 값 동일. 불필요한 새 메모 생성 없음
저장/오류버튼·Ctrl+S 기존 경로. 제목 없음·파서 문제·알림 오류·DB 오류 안내 유지실패하면 창을 닫지 않고 입력 유지. Ctrl+S 성공 확인은 기존과 같음
취소/삭제×는 기존 Esc 핸들러. 메뉴→드래그→좁은 시간표→서랍→팝업의 현재 적용 가능한 단계 순서 유지. 삭제는 수정 시 확인 후서랍 닫기와 전체 입력 취소를 혼동하지 않음. 신규 자동 저장/추가 취소 확인 도입 없음
키보드 순서제목→시간 요약→방식→알림 프리셋→직접→상세→분류→보조 칩→열린 서랍→전체 편집→삭제(있을 때)→저장→헤더 날짜/시간표/닫기. Shift+Tab 역순메뉴/달력 기본 화살표 조작 보존. Enter는 제목 저장으로 연결 금지. 명시적 버튼 포커스의 기본 활성화는 보존
접근성색+체크+텍스트, 키보드 포커스선. 모든 아이콘·축약 컨트롤에 접근성 이름·툴팁. 설정 여부와 펼침 상태를 별도 전달긴 문자열의 원문 접근 가능, 100/125/150%에서 글자 크기 임의 축소 없음

데이터 계약은 values()·_rule_values()·save()를 기준으로 고정합니다. DB 스키마, 파서 의미, 전체 편집 기능, 전역 단축키 및 기존 배포물은 변경 범위 밖입니다.
